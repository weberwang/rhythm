# Rhythm 作息行为管理商业级 PRD

> 版本：V1.2 Commercial PRD  
> 日期：2026-06-07  
> 来源：基于 `docs/rhythm-sleep-routine-management-prd-2026-05-21.md` 与 V1.1 商业稿优化  
> 产品代号：Rhythm  
> 产品类型：跨平台作息行为管理 App  
> 文档目标：用于产品评审、商业评估、视觉方向确认、技术基线编写、模块拆分和上线验收

## 0. 文档结论摘要

Rhythm 不是睡眠记录工具，也不是医疗诊断产品，而是一个帮助长期晚睡用户持续回到稳定作息节奏的行为管理产品。

本版 PRD 的核心收束为三点：

- `用户价值`：帮助用户今晚更容易停下来，明天更容易理解偏离原因，接下来几天更容易恢复节奏。
- `留存逻辑`：通过睡前进入、次日反馈、原因标记、恢复建议和周复盘形成重复回访，而不是依赖一次性报告。
- `付费逻辑`：免费层先证明“我能帮你看清并开始调整”，付费层再承接“我能帮你持续改善并长期稳定”。

相较上一版，本版重点补齐以下内容：

- 明确问题定义、成功标准、非目标和首发范围边界。
- 增加可执行的用户故事、功能需求、状态矩阵和验收口径。
- 补齐平台、权限、数据、国际化、可访问性、隐私与商业假设。
- 将开放问题拆分为 `已决默认项`、`决策阻塞项`、`延期问题`。
- 增加显式风险台账，便于后续设计与研发阶段持续对齐。

## 1. 产品定位

### 1.1 一句话定位

Rhythm 是一个面向长期晚睡但有调整意愿的人群的作息行为管理 App，通过目标作息、睡前干预、结果反馈和恢复计划，帮助用户更早睡、更稳定地睡。

### 1.2 问题定义

当前主流睡眠产品通常存在三个错位：

- 更擅长记录结果，不擅长改变今晚的行为。
- 更擅长展示图表，不擅长解释“为什么又晚了”和“接下来怎么办”。
- 更擅长单次反馈，不擅长把失败后的恢复路径做得足够轻和可持续。

Rhythm 要解决的不是“如何收集更多睡眠数据”，而是“如何把晚睡这件模糊、重复、容易自责的事，变成可观察、可干预、可恢复的日常闭环”。

### 1.3 产品承诺

Rhythm 不承诺“治好睡眠问题”，而承诺帮助用户完成三件更具体的事：

- 看清自己和目标作息之间的偏移。
- 在睡前获得一个足够轻、足够具体的收尾动作。
- 熬夜后知道接下来两三天如何恢复，而不是陷入挫败感。

### 1.4 产品边界

Rhythm 是 `作息行为管理工具`，不是：

- 睡眠医学诊断产品
- 冥想或助眠内容产品
- 泛健康生活方式平台
- 社区陪伴或监督打卡产品
- 智能硬件配套数据看板

### 1.5 商业定位

Rhythm 的商业价值来自用户持续改善作息的过程，而不是更多图表本身。

免费层负责建立信任和基础闭环：

- 读取或补录睡眠结果
- 设置目标作息
- 查看最近表现
- 进入睡前模式
- 查看基础周报

付费层负责承接持续改善：

- 恢复计划
- 稳定度评分和解释
- 长期历史和高级热力图
- 工作日/休息日双目标
- 轮班/时差策略
- 高级周报、月报和高级小组件

### 1.6 平台与验证面假设

本 PRD 默认采用以下平台假设：

- `首发验证面`：iOS 真机优先，原因是健康数据授权和通知体验在首发阶段更容易验证闭环。
- `产品定位`：长期保持跨平台产品定义，但 Android 作为 V1.0 正式补齐平台。
- `验证方式`：首发阶段以真实睡眠数据接入、手动补录和提醒闭环为主要验证面，不以桌面端或 Web 作为首发目标。

以上属于 `默认假设`，不是永久产品结论。若后续商业优先级变化，应在后续版本修订。

## 2. 目标用户与任务

### 2.1 核心用户

首发核心用户是 20-35 岁、长期晚睡但有主观调整意愿的人。

典型特征：

- 白天知道自己需要早睡，晚上仍然拖延。
- 睡前常见行为是刷手机、追剧、游戏、加班、情绪反刍或无意识消耗时间。
- 第二天会后悔，但缺少稳定的反馈和下一步动作。
- 不想被“自律打卡”强压，也不需要医学诊断。
- 愿意为清晰反馈、轻量引导和好看的长期趋势付费。

### 2.2 高价值细分人群

| 人群 | 晚睡触发 | 价值切入点 | 商业潜力 |
| --- | --- | --- | --- |
| 远程办公/自由职业者 | 边界感弱、工作时间后移 | 建立自定义节奏和提醒边界 | 高 |
| 城市白领 | 压力累积、报复性熬夜 | 次日反馈和恢复计划 | 高 |
| 学生/年轻职场新人 | 娱乐拖延、目标感弱 | 低门槛睡前收尾动作 | 中 |
| 跨时区/出差用户 | 时区变化、节奏漂移 | 时区解释和双目标策略 | 中高 |
| 轮班用户 | 作息非常规 | 后续付费高级策略 | 中高，但首发复杂度高 |

### 2.3 暂不优先覆盖

- 需要临床睡眠干预的人。
- 主要诉求是呼吸暂停、深睡比例、医学睡眠评分的人。
- 主要需要情绪陪伴、社群监督或内容疗愈的人。
- 需要硬件级实时监测的人。

### 2.4 核心用户任务

用户不是来“看睡眠报告”的，而是来完成以下任务：

- 今晚到点时，我怎么更容易停止当前行为？
- 昨晚为什么又晚了？
- 我最近有没有变稳定？
- 熬夜之后，我接下来几天怎么补救？
- 我是否值得为更长期、更个性化的改善方案付费？

### 2.5 关键用户故事

- 作为一个长期晚睡的上班族，我希望在目标时间前收到不冒犯的提醒，这样我更容易开始收尾。
- 作为一个第二天容易自责的用户，我希望看到“比目标晚了多少”和“主要原因是什么”，而不是只有抽象评分。
- 作为一个偶发熬夜的用户，我希望系统告诉我未来两三天应该怎样恢复，而不是只告诉我失败了。
- 作为一个对隐私敏感的用户，我希望即使不授权健康数据，也能通过手动补录获得基本闭环。
- 作为一个愿意付费的用户，我希望高级能力能真正帮助我更稳定，而不只是多几张图表。

## 3. 产品目标与非目标

### 3.1 产品目标

首发阶段 Rhythm 要证明以下目标成立：

1. 用户愿意在首次使用时进入可用状态，而不是在权限、登录或设置阶段流失。
2. 用户愿意把“目标作息”作为持续反馈的参考系。
3. 睡前模式能够推动真实行为参与，而不是只形成次日查看型使用。
4. 次日反馈、原因标签和恢复建议能提高回访和留存。
5. 付费能力能围绕“持续改善”形成清晰购买理由。

### 3.2 非目标

首发版本不追求以下目标：

- 不追求医学级睡眠诊断和复杂生理指标解释。
- 不追求内容型陪伴产品能力，如冥想音频、白噪音库、社区打卡。
- 不追求复杂游戏化系统，如大量勋章、排行榜、连续打卡惩罚。
- 不追求首发阶段覆盖所有异常作息类型，尤其不强行完整覆盖轮班复杂场景。

### 3.3 北极星指标

`最近 7 天内有 3 天以上有效记录，且至少 1 次进入睡前模式的活跃用户数`

这个指标同时约束记录、反馈和行为干预，避免产品退化成纯图表工具。

### 3.4 首发关键指标

| 阶段 | 指标 | 首发目标 |
| --- | --- | --- |
| 激活 | 注册/进入可用状态完成率 | >= 70% |
| 授权 | 健康数据授权率 | >= 55% |
| 设置 | 目标作息设置完成率 | >= 65% |
| 首晚 | 首晚记录生成率 | >= 40% |
| 行为 | 睡前模式周使用率 | >= 25% |
| 反馈 | 原因标签补录率 | >= 30% |
| 复盘 | 周报打开率 | >= 35% |
| 留存 | D7 留存 | >= 25% |
| 留存 | D30 留存 | >= 12% |
| 商业化 | 订阅转化率 | 3%-5% |

### 3.5 预警指标

- 健康数据授权率低：onboarding 权限价值不清，或用户信任不足。
- 目标设置完成率低：表单负担过高，或目标概念不够直观。
- 睡前模式进入率低：入口、提醒时机或睡前价值感不足。
- D7 尚可但 D30 差：短期新鲜感存在，但长期行为价值不足。
- 付费墙曝光高但转化低：高级能力价值表达不够硬，或拦截时机过早。

## 4. 产品体验原则

### 4.1 目标时间是全局基准

所有判断都围绕用户自己的目标入睡时间和熬夜阈值展开，不使用固定的“几点后就是熬夜”标准。

设计含义：

- 热力图颜色表达相对偏移。
- 今日页优先展示“离目标差多少”。
- 周报解释“稳定度”和“达标率”，不制造医学评分感。

### 4.2 允许失败，不制造羞辱

晚睡不是失败惩罚，而是触发恢复路径。

设计含义：

- 避免“你又失败了”类文案。
- 明显晚睡后优先展示恢复建议。
- 颜色使用柔和风险色，不使用强烈警示红。

### 4.3 低门槛输入优先

产品不能让用户在疲劳状态下填写复杂内容。

设计含义：

- 原因标签优先点选。
- 常用标签默认不超过 8 个。
- 手动补录要快，不把用户拖进复杂健康表单。

### 4.4 数据可信但可修正

健康数据可能缺失、延迟或与用户感受不一致。

设计含义：

- 明确显示数据来源和可信状态。
- 自动记录允许手动修正。
- 授权失败时仍然提供手动闭环。

### 4.5 付费发生在高意图时刻

付费墙不应打断激活，而应出现在用户已经感知价值、并主动追求更深入改善时。

适合触发：

- 点击恢复计划详情。
- 查看 30 天以前历史数据。
- 查看稳定度解释。
- 打开月报或高级报告。
- 开启工作日/休息日双目标、轮班或时差模式。

不适合触发：

- 首次打开 App。
- 刚完成健康授权。
- 用户正在处理同步失败或手动补录时。

## 5. 核心闭环

Rhythm 的首发闭环为：

`接入数据 -> 设置目标 -> 睡前进入 -> 次日反馈 -> 标记原因 -> 恢复建议 -> 周复盘 -> 调整目标`

### 5.1 首次激活闭环

目标：2 分钟内让用户进入可用状态。

路径：

1. 看懂产品不是医疗诊断，而是作息行为管理。
2. 选择登录或匿名/稍后同步策略。
3. 授权健康数据，或进入手动记录路径。
4. 设置目标入睡时间和起床时间。
5. 选择柔性提醒策略。
6. 看到第一版今日作息面板。
7. 选择是否添加小组件。

### 5.2 晚间行为闭环

目标：让用户在入睡前少做一个拖延行为。

路径：

1. 到达提醒时间。
2. 用户从通知、小组件或今日页进入睡前模式。
3. 页面展示距离目标入睡的时间差。
4. 用户选择今晚状态。
5. 系统给出一个轻量收尾动作。
6. 用户退出 App，等待次日结果回收。

### 5.3 次日反馈闭环

目标：让用户理解偏离原因，并产生继续使用动力。

路径：

1. 第二天打开 App。
2. 今日页展示昨晚结果、偏移程度和连续表现。
3. 用户补一个晚睡原因标签。
4. 若明显晚睡，系统给出恢复建议。
5. 用户看到今天目标和本周趋势。

### 5.4 周复盘闭环

目标：把零散行为转成持续改善感。

路径：

1. 每周固定时间生成周报。
2. 用户看到达标率、稳定度、最晚入睡日和主要原因。
3. 系统给出下周建议目标。
4. 用户可调整策略、分享卡片或查看高级解释。

### 5.5 首发闭环成立判定

以下条件同时满足，可认为首发闭环成立：

- 用户可在无健康权限与有健康权限两条路径下都进入可用状态。
- 用户能在一周内至少完成一次睡前进入和一次次日反馈。
- 用户能理解“结果反馈”与“恢复建议”的关系，而不是把系统视为纯记录工具。
- 免费用户已能感知价值，付费触点不需要依赖强打断才能获得曝光。

## 7. 引导模块商业级设计要求

引导模块不是宣传页，而是首个激活漏斗。每一页都必须减少一个用户疑虑，并推动用户进入可用状态。

### 7.1 页面 1：欢迎价值页

目标：

- 让用户 3 秒内理解 Rhythm 的价值是“帮我今晚少熬一点”，而不是“又一个睡眠报告”。

主信息：

- 产品承诺：看见偏移，今晚轻一点回到节奏。
- 三个价值点：睡前收尾、次日反馈、恢复计划。

主动作：

- 开始调整作息

验收：

- 不出现医疗诊断暗示。
- 不堆砌功能点。
- 首屏必须有明确的行为改善承诺。

### 7.2 页面 2：登录选择页

目标：

- 建立账户和同步信任，同时不让登录成为激活阻力。

主信息：

- 登录用于跨设备同步和数据恢复。
- 若首发允许匿名使用，应提供“稍后再说”路径。

主动作：

- Apple 登录 / Google 登录 / 邮箱登录

状态要求：

- 登录失败
- 用户取消登录
- 网络不可用
- 匿名继续

验收：

- 不在此页展示付费墙。
- 隐私和同步说明必须简短可读。

### 7.3 页面 3：睡眠数据授权页

目标：

- 提升健康数据授权率，并给授权失败用户保留手动路径。

主信息：

- Rhythm 读取什么：入睡、起床、睡眠时长。
- Rhythm 不做什么：不读取无关健康数据，不做医疗诊断。
- 用户得到什么：自动生成结果反馈和趋势。

主动作：

- 授权读取睡眠数据

次动作：

- 暂时手动记录

状态要求：

- 授权成功
- 授权拒绝
- 平台不可用
- 权限已开但数据为空

验收：

- 权限文案必须服务信任，不使用恐吓或夸大效果。
- 授权失败后仍可进入目标设置。

### 7.4 页面 4：目标作息设置页

目标：

- 建立全局判断基准，让后续所有反馈都有参照。

必填项：

- 目标入睡时间
- 目标起床时间
- 熬夜阈值
- 一天起始时间

高级项可后置：

- 工作日/休息日双目标
- 轮班模式
- 时区策略

验收：

- 默认值要能让用户快速完成。
- 时间选择不能显得像复杂设置页。
- 文案强调“目标可以调整”，降低心理压力。

### 7.5 页面 5：提醒策略设置页

目标：

- 让用户愿意开启提醒，但不制造打扰感。

提醒策略：

- 柔性提醒：目标前 30-60 分钟提醒收尾。
- 到点提醒：到目标时间轻提醒。
- 周报提醒：固定时间提醒回顾。

默认策略：

- 默认开启柔性提醒。
- 延迟提醒默认谨慎开启或后置。

验收：

- 不使用强监督、强打卡语气。
- 允许用户跳过，但要说明跳过后的影响。

### 7.6 页面 6：小组件引导页

目标：

- 建立桌面存在感，提高睡前模式入口可达性。

主信息：

- 小组件用于快速查看今晚目标和进入睡前模式。
- 不把小组件包装成装饰主题卖点。

主动作：

- 查看添加方式 / 稍后添加

验收：

- 小组件价值必须和睡前行为闭环绑定。
- 添加失败或平台不支持时给出降级说明。

### 7.7 页面 7：完成过渡页

目标：

- 从设置流程自然过渡到今日页，让用户看到第一版可用状态。

主信息：

- 已准备好今晚目标。
- 下一步是今晚到点时进入睡前模式。

主动作：

- 进入今日作息面板

验收：

- 不在此处强推订阅。
- 不制造“完成任务”的游戏化庆祝压力。

## 8. 核心模块需求

### 8.1 今日页

页面角色：每日回访入口和核心状态面板。

首屏必须回答：

- 昨晚怎么样？
- 今晚目标是什么？
- 我现在下一步该做什么？

核心区块：

- 昨晚结果卡
- 今晚行动卡
- 恢复建议卡
- 快捷记录卡
- 7 天趋势卡

关键状态：

- 无健康权限
- 有权限但无数据
- 昨晚达标
- 昨晚轻微偏离
- 昨晚明显晚睡
- 数据同步失败
- 已手动修正

功能要求：

- 免费用户必须能看懂核心结果。
- 恢复建议必须在明显晚睡时优先前置。
- 用户可直接进入补录、标签补充或睡前模式。

### 8.2 日历页

页面角色：长期反馈和可视化信任建立。

核心区块：

- 月度摘要
- 热力图
- 筛选模式
- 单日详情

筛选模式：

- 入睡时间
- 稳定度
- 晚睡次数

功能要求：

- 热力图颜色必须基于目标时间偏移。
- 缺失数据必须显示为未记录或待补录。
- 点击单日后能解释结果，而不只是展示数字。

### 8.3 睡前页

页面角色：今晚执行页。

首屏必须回答：

- 距离目标还有多久？
- 我今晚处于什么状态？
- 现在做哪一个小动作？

状态选择：

- 准备睡觉
- 还想拖一会儿
- 今晚大概率会晚睡

动作建议：

- 10 分钟收尾
- 先放下手机
- 明早再处理
- 关闭刺激源

功能要求：

- 从通知或小组件进入后，关键路径不超过 3 次点击。
- 夜间视觉低刺激，但按钮和状态必须清晰。
- 用户完成状态选择后，应当留下可用于次日解释的行为线索。

### 8.4 洞察页

页面角色：复盘、解释和付费承接。

核心区块：

- 本周达标率
- 作息稳定度
- 晚睡原因分布
- 恢复效果
- 周报入口
- 月报或高级报告入口

功能要求：

- 免费层展示基础摘要。
- 付费层解锁解释、恢复计划、历史趋势和高级报告。
- 每个图表旁必须有一句可行动结论。

### 8.5 我的页

页面角色：信任、配置和账户能力入口。

核心区块：

- 账户信息
- 会员状态
- 数据接入状态
- 目标作息设置
- 提醒设置
- 同步与隐私
- 小组件与主题

功能要求：

- 重要隐私和数据入口可被找到。
- 会员入口可见但不喧宾夺主。

### 8.6 跨模块通用需求

- 所有用户可见文案必须支持国际化。
- 同一个睡眠结果必须可追溯数据来源：自动读取、手动补录、手动修正。
- 任何依赖权限、网络、同步的关键能力都必须提供降级路径。
- 任何付费锁定都必须先展示价值，再展示升级理由。

## 9. 状态矩阵

生产级设计必须覆盖以下状态：

| 状态 | 影响页面 | 设计处理 |
| --- | --- | --- |
| 首次加载 | 启动页、引导页、今日页 | 品牌等待态，避免空白 |
| 健康权限未授权 | 授权页、今日页、我的页 | 明确价值和手动路径 |
| 权限已授权但无数据 | 今日页、日历页 | 解释数据延迟，提供手动补录 |
| 数据同步失败 | 今日页、我的页 | 页内提示和重试 |
| 手动修正 | 今日页、日历详情 | 标注修正来源 |
| 昨晚达标 | 今日页、日历页 | 正向但克制反馈 |
| 轻微偏离 | 今日页、日历页 | 温和提示下一步 |
| 明显晚睡 | 今日页、洞察页 | 优先恢复建议 |
| 标签为空 | 次日反馈、日历详情 | 轻量标签入口 |
| 恢复计划锁定 | 今日页、洞察页 | 高意图付费承接 |
| 历史数据锁定 | 日历页、洞察页 | 展示免费边界和升级价值 |
| 时区变化 | 今日页、日历页、我的页 | 暂停普通判断，提示确认 |
| 轮班模式未启用 | 目标页、我的页 | 作为高级策略入口 |
| 网络不可用 | 登录、同步、会员 | 降级可用，不阻断本地闭环 |

## 10. 数据、权限与集成假设

### 10.1 核心对象

- `User`：用户基础信息、地区、时区、语言、会员状态。
- `GoalSchedule`：目标入睡、目标起床、熬夜阈值、一天起始时间、工作日规则。
- `SleepRecord`：日期、入睡、起床、总时长、数据来源、可信度、修正状态。
- `BedtimeSession`：触发方式、进入时间、睡前状态、建议动作、完成状态。
- `SleepDelayTag`：日期、原因标签、是否系统推荐、是否自定义。
- `RecoveryPlan`：触发原因、计划周期、建议动作、查看状态、完成状态。
- `Report`：周期、达标率、稳定度、主要原因、建议摘要。
- `NotificationSetting`：提醒类型、提前量、开关状态、周报提醒。

### 10.2 核心计算

- `达标`：实际入睡时间 <= 目标入睡时间 + 熬夜阈值
- `晚睡分钟数`：实际入睡时间 - 目标入睡时间
- `作息稳定度`：最近 7 天入睡时间偏差的简化模型
- `周达标率`：最近 7 天达标天数 / 有效记录天数
- `恢复成功`：触发恢复计划后的 3 天内，至少 2 天回到阈值内
- `有效记录天`：存在系统记录或手动补录的日期

### 10.3 数据来源与权限假设

- 自动数据优先来自系统健康数据能力。
- 当自动数据不可用、为空或延迟时，手动补录必须成为一等路径，而不是兜底角落功能。
- 提醒能力依赖系统通知权限，但提醒关闭不应阻断产品主闭环。
- 账户同步默认作为增强能力，不应阻断本地首用体验。

### 10.4 集成范围假设

- 睡眠数据接入：首发优先支持系统健康数据聚合能力。
- 本地通知：用于柔性提醒、到点提醒、周报提醒。
- 本地存储：用于目标作息、补录记录、标签与会员缓存。
- 云同步：用于跨设备恢复、订阅状态同步、长期数据备份。

### 10.5 数据可信性要求

- 必须展示数据来源标签。
- 自动数据被手动修正后，原始记录不得被静默覆盖。
- 当数据缺失或晚到时，系统必须明确告诉用户“当前判断不完整”。

## 12. 商业化方案

### 12.1 免费层价值

免费层必须让用户确认产品值得留下：

- 最近 30 天记录
- 基础热力图
- 今日结果反馈
- 基础睡前提醒
- 基础原因标签
- 基础周报摘要

### 12.2 付费层价值

付费层必须提供“持续改善”的理由：

- 无限历史数据
- 恢复计划详情
- 稳定度评分解释
- 月报和高级周报
- 工作日/休息日双目标
- 轮班/时差模式
- 高级小组件
- 跨设备深度同步

### 12.3 付费触点

优先触点：

- 用户点击恢复计划。
- 用户查看稳定度详细解释。
- 用户查看 30 天以前历史数据。
- 用户打开月报或年度报告。
- 用户开启高级目标策略。

触点原则：

- 先展示一部分价值，再提出升级。
- 付费墙解释用户将获得什么改善，不只列功能。
- 年付作为主推，但不使用过度折扣和焦虑倒计时。

### 12.4 定价建议

中国区：

- 月会员：12-18 元
- 年会员：68-128 元
- 永久会员：168-248 元

海外：

- 月会员：2.99-4.99 USD
- 年会员：19.99-39.99 USD
- 永久会员：49.99-79.99 USD

## 13. 设计系统与体验方向要求

### 13.1 视觉方向

Rhythm 的商业级视觉应保持：

- 清醒
- 温和
- 克制
- 有秩序感
- 低压迫

避免：

- 医疗监测仪表盘感
- 大面积蓝紫梦境套路
- 过度冥想、香薰、疗愈化表达
- 强打卡、强惩罚、强勋章游戏化

### 13.2 信息层级

每个核心页面必须有：

- 一个主焦点区
- 一个次级解释区
- 一个辅助操作区
- 一个明确主动作
- 不与主动作竞争的次动作

### 13.3 状态色

状态色围绕目标时间偏移：

- 接近目标：青绿
- 轻微偏离：柔和琥珀
- 明显偏离：低饱和珊瑚
- 缺失或未知：中性灰蓝

### 13.4 文案语气

推荐表达：

- “今晚轻一点回到节奏”
- “昨晚比目标晚了 24 分钟”
- “接下来两天先把目标放稳”
- “先做一个 10 分钟收尾”

避免表达：

- “你又失败了”
- “必须早睡”
- “治疗失眠”
- “彻底解决焦虑”
- “马上变自律”

### 13.5 商业级设计验收

页面设计稿进入研发前必须满足：

- 3 秒内能读懂主任务。
- 首屏只有一个视觉重心。
- 用户可见文案真实，不使用占位文案。
- 覆盖理想、空、加载、错误、权限、部分数据、付费锁定状态。
- 付费触点不会破坏激活和核心闭环。
- 组件可复用，不依赖一次性装饰。
- HIG 行为基线不被破坏。

## 14. 国际化、可访问性与信任要求

### 14.1 国际化

- 首发用户可见文案必须具备国际化资源承载能力。
- 中文和英文是首批必须支持的文案基线。
- 文案设计需避免依赖中文特有语义才能成立的体验逻辑。

### 14.2 可访问性

- 关键状态色不能作为唯一信息表达方式，必须有文字或图标辅助。
- 睡前模式必须保证夜间环境下的可读性和点击清晰度。
- 关键按钮、通知文案和付费墙主动作必须避免认知歧义。

### 14.3 隐私与合规

全产品避免以下表达：

- 治疗
- 诊断
- 治愈
- 医学改善
- 精准评估失眠

推荐表达：

- 作息调整
- 行为改善
- 睡前习惯
- 节奏偏移
- 恢复建议

首发必须具备：

- 隐私政策入口
- 订阅条款入口
- 数据导出或删除路径说明
- 健康数据读取范围说明
- 手动数据和自动数据的来源标识

### 14.4 信任建立重点

信任建立优先发生在：

- 健康授权前
- 同步设置页
- 数据异常提示
- 会员付费前
- 隐私和导出入口

## 15. 上线验收标准

### 15.1 产品验收

- 首次安装到首页可用时间不超过 2 分钟。
- 健康授权失败时仍可通过手动路径完成闭环。
- 首页 3 秒内可读懂昨晚结果和今晚目标。
- 睡前模式路径不超过 3 次点击。
- 热力图正确反映目标时间偏移。
- 晚睡后优先展示恢复路径，而不是失败惩罚。

### 15.2 商业验收

- 免费层能清晰证明核心价值。
- 付费墙只出现在预设高意图场景。
- 年付方案为主推，价格梯度清晰。
- 付费能力围绕持续改善，不只围绕图表数量。

### 15.3 设计验收

- 引导模块每页都有明确商业目的。
- 核心页面覆盖非理想状态。
- 文案符合温和、克制、不医疗化的语气。
- 设计稿可拆成组件、状态和验收项。

### 15.4 技术验收

- 睡眠记录同步失败有明确提示和重试。
- 手动修正不破坏原始记录。
- 时区变化后不直接按普通规则误判。
- 推送时间按用户目标作息触发。
- 订阅状态可跨设备同步。

## 17. 问题台账

### 17.1 已决默认项

| 项目 | 当前结论 | 类型 | 理由 | 风险 |
| --- | --- | --- | --- | --- |
| 首发验证平台 | iOS 真机优先 | defaultable | 健康数据与通知闭环更易验证 | Android 价值验证滞后 |
| 产品形态 | 跨平台长期产品 | resolved | 商业目标不是单平台工具 | 首发资源压力更高 |
| 手动路径 | 作为一等路径保留 | resolved | 否则健康授权失败会直接破坏闭环 | 数据质量参差需额外解释 |
| 付费策略 | 高意图触点后置 | resolved | 避免伤害激活与信任 | 早期营收速度较慢 |
| 视觉气质 | 温和、克制、非医疗化 | resolved | 与行为改善定位一致 | 若执行不稳，容易变得平淡 |

### 17.2 待确认的决策阻塞问题

以下问题不会阻塞当前 PRD 成稿，但会阻塞后续“最终产品设计方向确认”：

- 首发是否允许匿名本地使用，还是必须登录后进入。
- 首发市场优先中国区、英语区，还是双语同步。
- 会员定价策略更偏低价高转化，还是中价位高价值表达。

### 17.3 延期问题

以下问题记录为后续版本决策，不阻塞当前 PRD：

- 轮班与时差模式是否在 V1.0 同步上线，还是放入后续高级能力版本。
- AI 周复盘是否完全后置，不进入首发设计稿。
- 年度报告、社交监督和内容型功能是否纳入长期路线图。

## 18. 风险与缓解

| 风险 | 影响 | 缓解策略 |
| --- | --- | --- |
| 健康权限授权率低 | 激活漏斗受损 | 强化权限价值说明，并保持手动路径同等可达 |
| 睡前模式进入率低 | 北极星指标无法成立 | 优化提醒时机、入口密度和睡前页首屏价值 |
| 自动数据延迟或缺失 | 用户信任受损 | 明示数据来源与延迟状态，允许快速补录与修正 |
| 付费能力表达弱 | 转化率低 | 围绕“恢复、稳定、长期改善”重构付费叙事 |
| 视觉方向过度疗愈化或过度工具化 | 品牌辨识度和商业调性失衡 | 在设计冻结前严格遵守非医疗化、非模板化约束 |
| 首发范围过大 | 交付节奏失控 | 强制按 P0/P1/P2 分层推进，不把轮班等复杂场景塞进首发闭环 |

## 19. 产品设计冻结卡

### 19.1 必须保持一致

- 产品本质是作息行为管理，不是睡眠医学诊断。
- 目标时间是所有反馈和颜色判断的基准。
- 晚睡后优先恢复建议，不做羞辱式反馈。
- 引导模块必须服务激活完成率和健康授权信任。
- 免费层给结果，付费层给持续改善。

### 19.2 允许后续工程化调整

- 具体热力图形态可根据 Flutter 实现稳定性调整。
- 初版稳定度模型可使用简化规则。
- 小组件引导可先做静态说明，再接真实平台能力。
- 高级能力可先展示入口和锁定说明，后续逐步补齐。

### 19.3 不可偏离

- 不使用医疗化、治愈化文案。
- 不在首开和授权后立即强推付费墙。
- 不把 onboarding 做成纯品牌介绍页。
- 不把洞察页做成复杂医学仪表盘。
- 不让用户在睡前填写重表单。

## 20. 结论

Rhythm 的商业机会不在“记录睡眠数据”，而在帮助用户把晚睡这个模糊、反复、容易自责的问题，转成一个可以每天轻量推进的行为闭环。

首发版本只需要把一条链路做扎实：

`今晚提醒 -> 睡前收尾 -> 次日反馈 -> 原因标签 -> 恢复建议 -> 周复盘`

如果这条链路成立，Rhythm 才有资格继续扩展到订阅、高级报告、跨平台同步、时差轮班策略和 AI 周复盘。

本 PRD 已经足以作为下一阶段 `产品最终设计方向确认` 的输入，但在进入视觉方向确认前，仍需明确登录策略、首发市场语言策略和定价姿态这三个商业关键点。
