# Rhythm 日历页顶部筛选栏语义对齐设计

> 版本：V1.0
> 日期：2026-05-25
> 适用对象：`lib/features/calendar/presentation/calendar_page.dart`
> 关联文档：`docs/superpowers/plans/2026-05-24-stage6-calendar-tag-closure.md`

## 一、背景与目标

当前日历页顶部红框区域由 `全部日期`、`晚睡 0 天`、`筛选` 三个组件组成，实现在 [calendar_page.dart](D:/Projects/Flutter/rhythm/lib/features/calendar/presentation/calendar_page.dart:95) 附近，采用 `_CalendarChip` 与 `ActionChip` 混排的 `Wrap` 结构。

现状问题不在于间距或尺寸，而在于语义不一致：

- `全部日期` 属于当前条件摘要
- `晚睡 0 天` 属于当前统计摘要
- `筛选` 属于操作入口

这三类信息目前被渲染成近似同类的胶囊，用户会自然理解为三个平级控件，从而产生“都能点”或“都表示筛选状态”的误读。

本次设计目标如下：

- 将顶部区域从“3 个平级胶囊”重构为“摘要栏 + 操作入口”
- 明确区分条件摘要、统计摘要、筛选动作三种语义
- 保持现有筛选逻辑、数据来源和弹层行为不变
- 为后续实现提供稳定的组件边界、小屏策略和测试口径

## 二、范围与非目标

本次仅调整显示层结构和文案映射，不涉及以下内容：

- 不修改 `CalendarFilter` 领域模型
- 不修改 `CalendarMonthSummary` 输出结构
- 不修改 `calendarControllerProvider` 的数据聚合逻辑
- 不修改 `calendar_filter_sheet.dart` 的筛选行为
- 不扩展新的筛选维度
- 不重做整页视觉主题

本次工作默认只处理日历页顶部红框区域。

## 三、现状判断

当前顶部区域的问题主要有三类：

### 3.1 语义混排

`_CalendarChip` 和 `ActionChip` 被同时放入一个 `Wrap` 中，视觉上同级，职责上却并不相同，导致“摘要”和“操作”边界模糊。

### 3.2 视觉暗示错误

`筛选` 作为唯一可点击入口，与左侧两个摘要项共享接近的胶囊语言，用户容易预期三个组件都可交互。

### 3.3 小屏演进风险

后续若顶部条件进一步扩展，继续沿用混排方案会让显示层不断在“状态胶囊”和“动作按钮”之间堆叠，语义和排布都会越来越不稳定。

## 四、方案对比

### 方案 A：摘要区与操作区分离

- 左侧承接摘要信息
- 右侧保留唯一筛选入口
- 摘要不可点击，按钮可点击

优点：

- 语义最准确
- 组件边界清晰
- 便于后续扩展更多摘要而不污染操作语义

缺点：

- 三个组件不再追求“同类外观”

### 方案 B：全部改成筛选控件

- 将 `全部日期`、`晚睡 0 天`、`筛选` 都改成可交互筛选器

优点：

- 交互形式统一

缺点：

- 会扭曲 `晚睡 0 天` 作为统计摘要的真实含义
- 需要新增不必要的筛选逻辑和状态同步

### 方案 C：只保留一个筛选按钮，摘要回收到文案说明

- 红框区域只保留 `筛选`
- 当前条件和统计改写到副标题或按钮下方说明中

优点：

- 版面最干净

缺点：

- 摘要信息扫描效率下降
- 失去顶部胶囊式即时反馈

### 结论

采用方案 A：`摘要区 + 操作区` 分离。

## 五、最终结构设计

顶部区域统一定义为一个 `CalendarFilterBar`，而不是三个平级胶囊。

整体结构如下：

1. 左侧摘要区
2. 右侧操作区

推荐显示层结构：

```dart
Row(
  children: [
    Expanded(
      child: Wrap(
        spacing: 8,
        runSpacing: 8,
        children: [
          _CalendarSummaryChip(...), // 条件摘要
          _CalendarSummaryChip(...), // 统计摘要
        ],
      ),
    ),
    const SizedBox(width: 12),
    _CalendarFilterButton(...),
  ],
)
```

设计理由如下：

- 左侧负责回答“我现在看到什么”
- 右侧负责回答“我要去哪里改条件”
- `筛选` 按钮不再参与摘要换行
- 顶部语义从“并列项”收口为“状态 + 操作”

## 六、摘要与按钮语义

### 6.1 条件摘要

条件摘要只表达当前筛选条件，不承担点击行为。

文案映射规则：

- 无筛选：`全部日期`
- 仅 `onlyRecordedDays = true`：`仅记录`
- 仅 `lateOnly = true`：`仅晚睡`
- 两项同时为 `true`：`已筛选 2 项`

设计原因：

- 双筛选同时生效时，继续并列展示两个条件胶囊会放大布局波动
- 汇总为一条条件摘要，更利于控制宽度和小屏表现

### 6.2 统计摘要

统计摘要只表达结果，不承担筛选语义。

文案规则固定为：

- `晚睡 X 天`

设计原因：

- 该信息属于月份统计结果
- 不应被用户误解为筛选器或可切换条件

### 6.3 筛选按钮

右侧按钮文案固定为：

- `筛选`

行为规则：

- 始终是顶部区域唯一点击入口
- 点击后打开 `calendar_filter_sheet.dart`
- 当存在激活筛选时，只改变按钮视觉激活态，不把状态摘要塞进按钮文案

## 七、视觉与排版规则

本次不重定义整页视觉，只在现有深绿体系中重新分配语义层级。

### 7.1 尺寸

- 条件摘要高度：`48`
- 统计摘要高度：`48`
- 筛选按钮高度：`48`
- 摘要胶囊圆角：`24`
- 按钮圆角：`24`
- 摘要胶囊横向内边距：`16`
- 按钮横向内边距：`18`
- 左侧摘要间距：`8`
- 摘要区与按钮间距：`12`

### 7.2 样式层级

- 条件摘要：低强调实底，无明显点击感
- 统计摘要：弱一级的中性或提示色底，用于表达信息状态
- 筛选按钮：描边或高对比样式，保留清晰点击暗示

核心原则：

- 摘要像标签
- 操作像按钮

### 7.3 图标策略

筛选按钮可以追加筛选图标，但摘要胶囊不加操作型图标，避免再次混淆。

## 八、小屏与换行策略

小屏下的优先级规则如下：

- `筛选` 按钮必须完整显示
- 左侧摘要区允许换为两行
- 条件摘要过长时优先使用 `已筛选 2 项`
- 不允许将 `筛选` 按钮挤到下一行
- 不允许隐藏统计摘要

设计原因：

- 操作入口是刚性能力，必须稳定可点
- 摘要是状态反馈，可以在有限范围内压缩表达

## 九、无障碍与语义输出

顶部区域不仅需要视觉语义正确，也需要语义树正确。

建议语义规则如下：

- 条件摘要：`readOnly`
- 统计摘要：`readOnly`
- 筛选按钮：`button`

按钮辅助说明建议：

- 无筛选时：`打开筛选`
- 有筛选时：`打开筛选，当前已启用筛选`

这样屏幕阅读器不会把三个组件误判为同类交互控件。

## 十、组件边界建议

为避免后续继续在页面里混排不同语义组件，建议将顶部区域拆分为以下显示层组件：

- `_CalendarFilterBar`
- `_CalendarSummaryChip`
- `_CalendarFilterButton`

建议职责如下：

- `_CalendarFilterBar`：负责整行布局和数据装配
- `_CalendarSummaryChip`：只负责只读摘要显示，不接点击事件
- `_CalendarFilterButton`：只负责统一筛选按钮样式和交互态

这样可以把“摘要不可点、按钮可点”的约束固化在组件边界里。

## 十一、国际化要求

若现有 ARB 资源尚未覆盖以下文案，需要补充国际化键值：

- `仅记录`
- `仅晚睡`
- `已筛选 2 项`
- `晚睡 X 天` 的参数化表达
- `打开筛选`
- `打开筛选，当前已启用筛选`

新增文案必须同步进入 `app_en.arb` 与 `app_zh.arb`，并通过 `flutter gen-l10n` 生成。

## 十二、测试建议

本次实现完成后，建议至少补齐以下显示层与交互测试：

- 默认状态显示 `全部日期`、`晚睡 X 天`、`筛选`
- 仅记录筛选时显示 `仅记录`
- 仅晚睡筛选时显示 `仅晚睡`
- 双筛选同时生效时显示 `已筛选 2 项`
- 顶部区域只有 `筛选` 入口具备点击行为
- 点击 `筛选` 后仍可正常打开筛选弹层
- 小屏宽度下顶部区域无溢出

这些测试可以优先落在 `test/features/calendar/calendar_page_test.dart`。

## 十三、结论

本次顶部区域优化的核心不是调整三枚胶囊的间距，而是纠正它们的语义关系。

最终收口方向为：

- 左侧两个只读摘要
- 右侧一个唯一操作按钮
- 通过结构、样式、文案、无障碍语义四个层面共同表达“状态”和“动作”的区别

在不改动业务逻辑的前提下，这一方案可以显著提升顶部区域的信息诚实度、扩展稳定性和小屏可控性。
