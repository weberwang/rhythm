## 1. 设计简报

- 目标用户：长期晚睡、希望改善作息但不接受羞辱式监督的人群。
- 使用时刻：
  - 睡前疲劳、注意力稀缺时的低刺激引导
  - 次日快速回看昨晚结果与恢复建议
  - 周期性复盘与高意图升级时刻
- 产品承诺：帮助用户看清与目标节奏的偏移，并在今晚和接下来几天更容易回到节奏。
- 商业目标：
  - 激活：用户理解产品不是“另一个睡眠报告”
  - 留存：用户形成“每天回来看看并继续下一步”的习惯
  - 转化：在恢复计划、稳定度解释和长期趋势处建立付费理由
- 页面范围：全局共享显示层方向，覆盖引导、首页、睡前、日历、洞察、我的及其关键状态，不进入单模块页面级冻结
- 硬约束：
  - 默认遵循 `ios_hig`
  - 不允许医疗化、惩罚化、高密度 dashboard 化
  - 必须覆盖理想态、空态、加载态、错误态、权限态、部分数据态、锁定态

## 2. 平台基线

- 默认平台基线：`ios_hig`
- 保持项：
  - 安全区、点击热区、底部导航、返回行为、破坏性动作分层、权限请求时机遵循 iOS 预期
  - 动效只承担反馈、层级切换和轻确认角色
- 不保留“原生默认感”的方式：
  - 通过排版层级、空间节奏、细边框卡片和材料深度去原生
  - 不靠玻璃、渐变、霓虹或大图装饰去原生

## 3. 当前设计诊断

- 当前已存在的历史全局设计资产方向基本正确，但在当前重置后的工作流里还没有被重新登记为共享 taste direction。
- 若直接从模块草稿进入下游实现，主要风险不是“风格不够好看”，而是：
  - 模块会各自放大不同的层级习惯，导致首页、睡前、洞察语气不一致
  - 工程侧容易把“温和克制”误还原成“普通浅色列表”
  - 会员触点、权限触点、恢复建议触点可能被局部页面重新排序，破坏商业路径
- 当前最需要先锁定的不是新颜色，而是：
  - 首屏单主焦点规则
  - CTA 主次关系
  - 轻量材料层次
  - 作息产品应有的情绪温度
  - 生产态覆盖范围

## 4. 设计师批评

- `focal intent`：Rhythm 的核心体验不是“看很多数据”，而是“立刻知道现在发生了什么”。因此任何主屏若没有单一焦点，都会伤害产品价值感。
- `task guidance`：若首页、睡前页和引导页没有稳定的“现在 -> 下一步”节奏，用户会把产品理解成静态信息容器，而不是行为引导工具。
- `type ladder`：商业级完成度的关键不是更多修饰，而是标题、结果、解释、标签、辅助操作必须形成非常明确的阅读深浅。
- `cta salience`：如果恢复建议、会员入口、设置入口和主动作看起来一样重，用户会失去对核心路径的判断。
- `composition balance`：Rhythm 需要一块 dominant zone、一块 secondary zone 和一块 support zone；否则就会退化成模板化功能集合页。
- `brand memory`：这个产品应该被记住为“平静但有秩序的节奏工具”，而不是“蓝白健康工具”或“深色效率工具”。

## 5. 方向对比

### 方向 A：Precision-Led Cool

- 特征：更冷静、更专业、更接近精密工具。
- 优点：规则感强，适合数据解释。
- 缺点：容易把作息产品推向冷硬、被监测的感受，不利于睡前和失败后恢复场景。

### 方向 B：Warm Calm Quiet Assistant

- 特征：暖纸感背景、克制层次、细边框卡片、低饱和松石主色、明确但不逼迫的 CTA。
- 优点：最符合睡前低刺激、次日恢复、长期回访和高信任商业路径。
- 缺点：如果层级控制不足，容易被工程实现稀释成“普通浅色卡片应用”。

### 方向 C：Dark Focus Premium

- 特征：深墨青背景、沉浸感强、夜间友好、视觉记忆更鲜明。
- 优点：夜间使用体验更有专属感。
- 缺点：若作为默认主方向，容易压缩日间轻松感，也更容易在首页与洞察页形成过度仪表盘气质。

## 6. 推荐方向

- 推荐方案：`方向 B：Warm Calm Quiet Assistant`
- 四轴结论：
  - `product_posture`: `quiet assistant`
  - `information_density`: `balanced`
  - `visual_temperature`: `warm calm`
  - `de_native_strategy`: `typography and rhythm` 为主，`material depth` 为辅
- 推荐理由：
  - 它最能兼容引导、首页、睡前、恢复、会员承接这几类场景，不会只对某一屏有效。
  - 它保留高信任和低压迫感，同时可以通过层级和材料深度避免“太原生、太平”。
  - 它最利于后续 Flutter 还原，因为主要依赖可系统化的排版、边框、间距和语义色，而不是难维护的装饰资源。

## 7. 艺术指导

- 产品姿态：安静、可靠、低评判、持续陪伴
- 信息密度：`balanced`
- 视觉温度：`warm calm`
- 品牌记忆点：
  - 暖纸感背景
  - 深海松石主色
  - 细边框和轻表面分层
  - 单一主焦点驱动的页面节奏
- 核心 polish levers：
  - `hierarchy`
  - `material`
- 不采用的主要手段：
  - hero 大图
  - 真照片
  - 强渐变
  - 重阴影
  - 情绪化大插画

## 8. 核心路径

1. 用户进入页面后，先读懂“现在发生了什么”
2. 用户立刻看到“下一步要做什么”
3. 用户在需要时得到解释，而不是被解释淹没
4. 用户完成动作后能回到一个更稳定、更可信的主视图
5. 当用户表现出高意图时，再看到升级价值

## 9. 信息层级

- dominant zone：
  - 引导页：产品价值承诺或单一关键选择
  - 今日页：昨晚结果
  - 睡前页：距离目标与今晚动作
  - 日历页：当前周期焦点
  - 洞察页：本周最值得理解的单一结论
- secondary zone：
  - 今晚行动、恢复建议、趋势摘要、单日解释
- support zone：
  - 设置、管理、历史、会员次入口、帮助说明
- CTA 规则：
  - 同屏只能有一个“必须先做”的主动作
  - 次动作必须在视觉上明显退后

## 10. 视觉系统

### Typography

- 大标题：衬线或衬线感标题，只用于页面身份和极少数关键数字标题
- 正文：中性无衬线，保证移动端可读性
- 结果数字：轻重量、大字号、宽呼吸，不使用粗黑冲击
- 元信息：明显降级，不与结果层竞争

### Contrast

- 主文本与背景对比满足生产可读性，不用“高级灰”牺牲速度
- 主 CTA 在 3 秒内必须可识别
- 错误与风险使用柔和珊瑚 / 暖橙，不使用高饱和警报红

### CTA Posture

- 主 CTA 负责“继续回到节奏”
- 次 CTA 负责“管理、稍后、更多信息”
- 会员 CTA 只能出现在主任务之后，不得抢占主焦点

### Spacing

- 8pt 基础节奏
- 主卡内边距优先 20-24pt
- 卡片与卡片之间必须保留明显呼吸

### Surface Model

- 主表面：暖背景 + 浅表面 + 细边框
- 辅助层次：轻微 surface shift，不靠厚重阴影
- dark 模式：必须保留卡片与背景边界，不允许整片糊成一层

### Shape / Border

- 全局圆角保持统一，不在局部页面另起一套语言
- 边框是主分层手段之一，不允许被完全去掉

### Icon / Illustration / Motion

- 图标：细线、低重量、轻几何感
- 插画：默认不提供系统级插画语言
- 动效：只承担切换、反馈、轻确认，不承担品牌记忆主角

## 11. 状态矩阵

| 状态 | 当前必须设计 |
| --- | --- |
| 理想态 | 是 |
| 空态 | 是 |
| 加载态 | 是 |
| 错误态 | 是 |
| 权限态 | 是 |
| 部分数据态 | 是 |
| 禁用态 | 是 |
| 成功态 | 是 |
| 锁定 / 会员态 | 是 |

### 状态总原则

- 任何状态都必须先解释当前情况，再给下一步
- 不允许把异常态只做成 toast 或灰字
- 会员锁定必须出现在已可用内容之后
- 权限拒绝必须始终保留继续路径

## 12. 商业化触点

- 高意图触点：
  - 恢复计划详情
  - 稳定度解释
  - 长期历史
  - 月报 / 高级洞察
  - 高级目标策略
- 商业表达原则：
  - 先让用户看到已获得的帮助，再解释更深价值
  - 升级叙事围绕“持续改善”和“长期回稳”
  - 不在首开、授权后或异常处理中强推付费

## 13. 共享设计冻结卡

### 必须一致项

- 所有主页面首屏只有一个主焦点
- 页面阅读顺序固定为“现在发生了什么 -> 下一步 -> 支撑解释 -> 管理入口”
- 全局保持 `warm calm`，不改成医疗蓝白、效率 dashboard 或霓虹暗黑
- 主 CTA 永远优先于会员、设置、说明和次动作
- 锁定内容永远晚于已可用内容出现
- 状态覆盖范围必须包含空、加载、错误、权限、部分数据、锁定

### 允许工程化调整项

- 局部卡片高度可因文案长度和多语言变化弹性伸缩
- 趋势微图、skeleton 细节、列表虚线/分隔的轻微表现可按 Flutter 组件实现调整
- 不引入插画语言的前提下，可省略静态氛围化装饰

### 平台不可偏离项

- 安全区、点击热区、破坏性动作分层、返回行为、权限请求时机遵循 `ios_hig`
- 不允许为了追求“高级感”破坏可点击性、可读性和单手触达
- dark 模式不可把卡片边界做没

### Prompt 约束

- 禁止 hero 图优先于任务本身
- 禁止大面积渐变、玻璃、霓虹描边
- 禁止多主卡并列竞争
- 禁止把同一页面做成看板式数据墙
- 禁止用羞辱式文案表达晚睡或失败

### 交付验收门

- 用户是否能在 3 秒内读懂当前页面主任务
- 用户是否能在 3 秒内找到主 CTA
- dominant / secondary / support 三层是否明显
- 页面是否覆盖生产态而不只覆盖 happy path
- Flutter 实现是否可以用组件、token 和状态规则复现，而不是依赖主观猜测

## 14. Flutter 实施护栏

- Flutter 显示层必须优先还原层级、节奏、CTA 优先级和状态覆盖，不要只抄颜色。
- 任何页面若为了实现方便而把单主焦点改成多卡并列，都视为偏离设计方向。
- 局部组件可做工程简化，但不得破坏“主结果优先、次动作退后、解释随后”的基本阅读节奏。
- 后续若使用静态预览包进入冻结，必须通过 `design-preview-to-global-guidelines` 重新生成当前工作流认可的全局设计合同，而不是直接把历史冻结文件当作自动生效结论。
