## design_position

本轮冻结唯一视觉基线为 `output/imagegen/rhythm-style1-review-fixes-2026-06-03/style-01r-bedtime-preview.png`、`output/imagegen/rhythm-style1-review-fixes-2026-06-03/style-01r-calendar-preview.png` 与 `output/imagegen/rhythm-style1-review-fixes-2026-06-03/style-01r-insights-preview.png`；后续若替换任一预览图，必须回退到全局设计冻结流程重新确认。

Rhythm 的全局设计定位是“温和克制的高信任作息节律管理工具”，而不是医疗监测面板、效率打卡器或情绪疗愈内容产品。界面需要传达的体验承诺是：用户在疲劳、晚睡挫败或恢复期波动状态下，仍然能迅速看懂当前节律、下一步动作与长期改善方向，并感受到产品在帮助自己“回到节奏”，而不是在评判自己。

## product_personality

产品个性应稳定保持以下特征：

- 冷静：通过低饱和蓝绿主色和大面积暖中性色背景建立稳定感。
- 克制：装饰存在，但只服务信息层级、空间呼吸和高级感，不服务炫技。
- 轻奢但不张扬：留白、柔和边界、细线图标和细致字阶共同构成高级感，而不是靠强对比或复杂纹理。
- 可信：核心数据、趋势总结和下一步动作都优先解释清楚，不用戏剧化视觉争夺用户注意力。
- 可回访：每一屏都保留一个清晰主行动，让用户在低认知负担下继续推进。

最应保持的可记忆视觉特征是：

- 暖白纸感背景 + 低饱和深海松石主色
- 轻边框卡片 + 大留白
- 圆点、圆环、进度徽记组成的轻量状态语言
- 无玻璃炫光、无霓虹渐变、无高对比告警式氛围的平静高级感

## target_users_and_core_scenarios

目标用户是长期晚睡、愿意调整节律但不希望被羞辱式监督的人群。典型使用场景包括：

- 睡前收尾：用户已经疲劳，注意力稀缺，需要一个低刺激、低负担的 wind-down 行动入口。
- 次日校准：用户希望快速知道昨晚相对目标偏移了多少，以及今天如何微调目标或补救。
- 周期复盘：用户希望通过趋势和稳定度理解自己，而不是只看一堆冷数据。
- 高意图升级：用户已经感受到产品价值，愿意为更深入的洞察、恢复建议和长期计划付费。

全局界面必须优先优化：

- 快速扫描
- 情绪不过载
- 状态解释清晰
- 触控目标舒适
- 低认知成本的继续动作

## global_experience_principles

- 永远先告诉用户“现在发生了什么”，再告诉用户“接下来做什么”。
- 所有主页面首屏都必须有一个单一主焦点，不允许多个同权重视觉主角竞争。
- 每一屏只允许一个清晰的主 CTA；高级权益或说明链接只能作为次级承接。
- 晚睡反馈是恢复入口，不是惩罚入口。
- 高级能力的价值表达应以“持续改善”叙事承接，而不是以“你看不到更多图表”施压。
- 权限、同步、数据缺失和锁定状态都必须是被设计过的一等状态，不能只靠 toast 或灰字补丁。
- 视觉上的平静感优先于密度堆叠；空间留白是功能性的，不是装饰性的。

## information_hierarchy_principles

- 每个核心页面的阅读顺序固定为：页面身份 -> 当前结果或当前任务 -> 下一步动作 -> 支撑解释 -> 次级管理入口。
- 顶部居中的 `Rhythm` 品牌字样是共享身份锚点，不得与页面大标题争夺首屏主焦点。
- 首屏一级信息只允许出现一个：倒计时、月历热力焦点、周达标率等；其余内容必须降为二级卡片。
- 统计数字必须与解释文案共生出现；数字不允许单独裸露成装饰性 KPI。
- 主 CTA 必须落在一级信息之后的最近可触达位置，且视觉权重显著高于说明链接、锁定入口与次级管理动作。
- 锁定/高级内容必须在视觉上明显晚于已可用内容出现，避免误导用户以为主功能被阻断。

## layout_and_page_structure_principles

- 页面骨架以竖向单列为主，使用宽松边距和连续卡片流构成节奏。
- 主页面共享顶部 chrome：左右功能图标夹住居中品牌字样，页面级大标题在下一层单独出现。
- 底部导航固定为 5 个 tab，顺序固定为 `Today / Plan / Bedtime / Insights / Profile`，不得在共享冻结之后改名、增删或换序。
- 卡片是全局主结构单元，但卡片之间要通过外边距、内边距和轻边框区分语义层级，不依赖重阴影。
- 核心主卡片可使用品牌色浅底或品牌主色实底，但同屏只允许 1 个高强调行动面。
- 允许使用左右分栏摘要卡承载“整体总结 + 单日详情/即时调整”结构，但必须确保一侧解释状态、一侧承接动作，不能都变成说明面板。
- 列表型内容使用“轻卡片 + 细分隔 + 足够呼吸”的方式承载，避免 dense dashboard 样式。

## component_system_principles

- 共享公共组件冻结范围至少包括：顶部品牌 chrome、底部导航、主行动按钮、次行动按钮、基础卡片、主行动卡、圆环统计卡、日历热力单元、洞察列表条目、锁定卡、进度徽记。
- 顶部品牌 chrome 的规则固定为：细图标、居中品牌字样、轻分隔线、页面标题下置；不得在局部页面切换成另一套头部语法。
- 底部导航必须保持统一的图标重量、标签字号、激活色与非激活对比；激活态仅允许一个 tab 使用品牌主色强调。
- 日历热力单元的共享状态必须至少覆盖：`on_goal`、`earlier`、`later`、`selected`、`no_data`；颜色差异服务语义，不服务装饰。
- 洞察列表条目采用“圆形前导状态图标 + eyebrow 标签 + 一句话解释 + 右侧箭头”的稳定结构，不允许混成多种列表语法。
- 锁定卡与高级权益卡必须保留“已可用内容在前、升级价值在后”的层级；它们是次级商业承接，不是首屏主角。
- 进度徽记、完成数与状态点属于系统级语义元素，可复用，但不能演化成高装饰的贴纸语言。

## interaction_behavior_principles

- 主按钮和主行动卡的点击区必须足够大，适合单手操作和疲劳状态点击。
- 一屏只允许一个实心主动作；说明链接、升级入口、次动作按钮必须降噪。
- Calendar 选中日期后必须给出明确后续路径，例如调整目标、查看当日详情或确认当前节律，不允许停留在纯展示状态。
- Insights 页优先引导用户消费当前可用建议，其后才承接高级权益；升级入口不得压过当前可用主 CTA。
- 交互反馈要克制清晰，优先用颜色、边框、轻位移和内容变化表达，不靠夸张动画。
- destructive 行为必须留在次级层或确认层，不得与主恢复动作并列。

## state_and_feedback_principles

- `ideal`：保持轻、稳、可继续动作，不做过度庆祝。
- `loading`：优先局部 skeleton 或占位，不轻易整页遮罩。
- `empty`：解释“如何开始”，而不是展示无意义空容器。
- `error`：页内可恢复，语气中性，不用系统化恐吓色块。
- `permission`：先解释价值，再解释限制，始终保留可继续路径。
- `partial-data`：明确告诉用户缺了什么，以及当前还能做什么。
- `disabled`：使用透明度、边框和文案组合表达，不做彻底消失。
- `success`：表达“你正在回到节奏”，不是任务完成游戏化奖励。
- `locked/premium`：先让用户理解已获得价值，再解释更深层内容为何值得升级。
- 共享可视状态语言在冻结层至少要明确：进度完成、日历偏移、无数据、锁定入口、主 CTA 激活与次 CTA 降权的表达边界。

## content_and_copy_principles

- 文案语气必须温和、直接、非命令式。
- 标题要短，说明文案只解释当前必要信息，不扩张成长段教育文本。
- 帮助文案优先回答“为什么我会看到这个”和“现在该做什么”。
- 警示和失败文案避免羞辱性词汇，不使用“失败”“必须”“立刻自律”等表达。
- 主 CTA 用词必须是明确动作，如 `View tips`、`Adjust goal`、`Continue wind-down`；说明型链接才允许使用 `Learn more` 一类表达。
- 高级能力文案以“更深入理解、持续改善、长期回稳”为主，而不是“解锁更多功能列表”。

## visual_system_rules

- Typography：
  - 产品名与页面大标题使用高对比衬线或衬线感标题风格，但产品名尺寸要低于页面大标题，不可反客为主。
  - 正文与功能标签使用中性无衬线，确保移动端可读性和稳定性。
  - 大数字需要轻重量、宽呼吸、低压迫感，不使用粗黑体冲击。
  - 图例、辅助说明、非激活导航标签和 eyebrow 文案必须保持移动端快速扫视可读性，不能被压成过浅的灰字层。
- Spacing：
  - 采用宽松的 8pt 基础节奏，核心卡片内边距倾向 20-24pt 区间。
  - 卡片与卡片之间间距必须明确，避免拥挤拼贴。
- Surface depth：
  - 主要靠暖背景、轻边框卡片与少量层级差形成结构。
  - 阴影极轻，仅作为微弱悬浮提示，不构成主要分层手段。
- Color：
  - 品牌主色为低饱和深海松石系。
  - 主 CTA 使用更深的品牌实色，次级强调面使用浅青灰或暖中性浅底。
  - 成功与稳定倾向柔和青绿，偏移/风险倾向柔和珊瑚与暖橙，而不是高饱和警报红。
- Icon posture：
  - 细线、低重量、轻几何感，保持理性与安静。
- Illustration posture：
  - 当前视觉证据中没有系统级插画语言，全局规则冻结为 `not_provided`。
- Motion role：
  - 仅用于层级切换、状态确认和轻卡片反馈。
  - 不允许把炫技 motion 当作品牌记忆主手段。
- Decorative limits：
  - 不允许全局玻璃化、强渐变、霓虹描边、大面积拟物纹理。
  - 预览图中的植物、织物、器皿、书本与摄影氛围仅是静态展示语境，不得转译成运行时 UI 装饰资源。

## light_theme_rationale

Light 主题采用温暖纸感背景、柔和白卡片和低饱和松石主色，是为了同时满足三件事：

- 保持作息产品需要的平静和信任，不落入医疗蓝白或效率工具冷硬感。
- 让倒计时、月历热力图、周达标率和主 CTA 在浅背景下获得高可读性而不刺眼。
- 通过暖中性底色配合深松石主色，形成“温和但有秩序”的商业级记忆点。

Light 模式下，浅青灰主行动卡与深松石实心按钮共同形成“主任务在前、说明承接在后”的行动层级。

## dark_theme_rationale

Dark 主题不能简单反相。它应保留 light 主题的安静、克制与高信任气质，同时控制夜间阅读眩光。

因此 dark 主题采用：

- 暖冷平衡的深墨青背景，而不是纯黑；
- 分层清晰但不过亮的深色 surface band；
- 亮度抬高但饱和度仍克制的主色与状态色；
- 更柔和的 overlay 与 focus ring，避免夜间刺眼。

Dark 模式的目标是让夜间使用更像安静灯下的仪表阅读，而不是霓虹高对比控制台。

## design_prohibitions

- 不得把品牌主色替换成高饱和蓝紫或强荧光色。
- 不得把核心页面重做成高密度 dashboard。
- 不得把晚睡反馈设计成羞辱、惩罚或红色警报式体验。
- 不得把静态预览里的环境静物、植物、书本等外部道具直接转译成应用内装饰资源。
- 不得把锁定内容视觉做得比已可用主内容更强势。
- 不得在共享冻结之后改写底部导航的数量、命名、顺序和激活语法。
- 不得让一屏出现多个实心同权重 CTA。
- 不得在局部页面自行改写全局卡片圆角、边框强度、标题层级和顶部品牌 chrome 语法。

## engineering_guardrails

- 运行时实现可以省略静态预览中的摄影级光影与外部道具氛围，但必须保留温暖背景、轻边框卡片、品牌主色节奏与层级克制。
- 允许为了适配动态内容长度而调整卡片高度，但不允许压缩全局留白节奏到模板化列表密度。
- 允许使用 Flutter 原生或自定义组件实现倒计时卡、圆环统计、热力图、状态卡与洞察列表，但必须保持冻结的色义、边界和 CTA 主次关系。
- 顶部品牌 chrome、底部导航顺序、Calendar 热力语义与 Insights 主 CTA 优先级是共享冻结的硬约束；实现不得自行重解释。
- Dark 主题不能从 light 主题自动算反色，必须显式映射到冻结文件中的语义值。
- 若后续某个模块需要大幅突破当前视觉系统，必须回到全局冻结流程，而不是局部自行扩展。
