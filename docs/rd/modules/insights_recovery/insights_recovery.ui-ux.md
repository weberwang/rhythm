# insights_recovery UI/UX RD

> 配对实现 RD：`docs/rd/modules/insights_recovery/insights_recovery.impl.md`
> 全局基线：`docs/rd/2026-06-02-rhythm-commercial-global-rd.md`
> 工作流状态：`modules_split`

## 1. 模块目标

把一周内的记录和原因转成可行动复盘，并在高意图场景承接恢复计划、稳定度解释和高级报告付费价值。

## 2. 目标用户

已经有多天有效记录、想知道自己是否变稳定、为什么晚睡、如何恢复的用户。

## 3. 页面范围与导航入口

- 洞察页
- 周报详情页
- 历史洞察页
- 恢复计划详情弹层
- 稳定度说明弹层

## 4. 核心用户路径

1. 用户进入洞察页。
2. 用户看到本周达标率、稳定度和主要原因。
3. 用户查看周报详情。
4. 用户在明显晚睡后查看恢复计划。
5. 用户在高级解释或历史入口遇到轻量付费承接。

## 5. 状态矩阵

| 状态 | 设计要求 |
| --- | --- |
| ideal | 一句结论 + 关键指标 + 下一步 |
| loading | 生成周报时可读等待 |
| error | 生成失败可重试 |
| permission | 数据不足时引导记录而非报错 |
| partial data | 少于 3 天有效记录显示数据不足 |
| disabled | 无目标时引导设置 |
| success | 周报生成后清晰展示 |
| locked | 恢复详情、稳定度解释、历史可付费承接 |

## 6. 设计来源

核对 Pencil 洞察页、周报详情、历史洞察、恢复计划详情、稳定度说明和付费墙。

## 7. 设计冻结卡

- 必须保持：每个图表旁有可行动结论，免费层给摘要，付费层给解释和改善。
- 可工程化调整：图表具体形式、历史列表密度。
- 不可偏离：不得做成复杂医学评分或羞辱式复盘。

## 8. 验收门槛

- 少于 3 天有效记录不生成正式周报。
- 恢复建议不医疗化。
- 付费触点出现在高意图时刻。
- 周报能指导下一周行动。
