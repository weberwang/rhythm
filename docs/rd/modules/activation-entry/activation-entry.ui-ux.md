# Activation Entry UI/UX RD

## 模块目标与目标用户

- 模块目标：在最低认知负担下完成产品价值理解、登录/匿名进入、权限建立和首轮激活交接。
- 目标用户：首次安装、首次回流、登录失败后重试、权限犹豫中的新用户。

## 页面范围与导航入口

- 页面范围：启动页、欢迎页、登录选择页、健康授权页、完成过渡页。
- 导航入口：`/launch` 启动分发；首次打开、登出后重进、权限重试场景进入。

## 平台基线

- 平台基线：`ios_hig`
- 说明：首启流程中的安全区、主按钮层级、权限调用节奏、返回行为和页面推进感遵循 iOS 基线；显示层必须继承 `docs/rd/global-design-guidelines.md` 与主题冻结文件，不得退化成系统默认欢迎页、营销轮播或设置列表。
- 工程落地边界：允许使用 Flutter 原生页面切换、底部抽屉和系统权限弹窗承载流程，但页面骨架必须保持单列、宽留白、细边框卡片和低刺激过渡，不得引入 dashboard 化模块拼贴。

## 商业目标

- 主要目标：提升激活完成率与健康授权信任感。
- 次要目标：让登录不成为阻塞，同时让匿名继续看起来是受尊重的可用路径。
- 业务闭环要求：激活完成后，用户必须已经理解“今晚目标如何建立”“后续数据如何帮助自己回到节奏”，而不是只完成账户或权限技术接入。

## 艺术指导

- 产品姿态：`quiet assistant`
- 信息密度：`sparse`
- 视觉温度：`warm calm`
- 去原生重心：`typography and rhythm`
- 设计记忆点：首启体验像“安静引导进入节奏”，而不是教程轮播或品牌广告页。
- 模块视觉语气：像一位克制的夜间引导员，先降低焦虑，再推进选择，不使用过度插画、夸张动效或高饱和强调条。

## 信息层级

- 主焦点区：单页唯一价值承诺或单一关键选择
- 次焦点区：简短解释与风险降低说明
- 支撑区：次动作、隐私/同步说明
- 主动作：继续进入下一步
- 次动作：匿名继续、稍后再说、查看必要说明
- 层级约束：
  - 启动页只承载品牌识别与状态判断，不承载营销信息。
  - 欢迎页只回答“这个产品帮你解决什么”。
  - 登录选择页只回答“现在用哪种方式继续”。
  - 权限页只回答“为什么现在要授权，以及不授权还能怎么走”。
  - 完成页只回答“已准备好进入今晚节奏”。

## 核心用户路径

1. 用户进入启动分发。
2. 系统判断首开、登录态、匿名态与基础配置状态。
3. 用户理解产品价值后选择登录或匿名继续。
4. 用户完成健康权限授权或进入手动路径。
5. 用户完成首轮交接并进入今日页。

## 状态矩阵

| 状态 | 表现要求 |
| --- | --- |
| 理想 | 2 分钟内完成激活，主动作单一明确 |
| 空态 | 首开无任何记录时，强调“今晚轻一点回到节奏” |
| 加载 | 启动页展示品牌等待态，不出现空白闪烁 |
| 错误 | 登录失败、网络失败、授权调用失败要有页内恢复动作 |
| 权限 | 健康权限拒绝后保留手动路径，不阻塞进入主链路 |
| 部分数据 | 已登录但无健康数据时，解释“先继续设置，稍后可补录” |
| 禁用 | 平台不支持某登录或健康能力时，展示降级说明 |
| 成功 | 激活完成页只强调“已准备好今晚目标”，不做庆祝式打扰 |
| 锁定/会员 | 本模块不出现付费锁定 |

## 模块级组件冻结骨架

- `onboarding_value_hero_card`
  - 用途：承载单句价值承诺与进入下一步的主上下文。
  - 状态：`default`、`loading`、`error_hint`。
  - 冻结约束：同屏只能有一个主价值卡，禁止叠加第二张营销卡竞争主焦点。
- `sign_in_method_stack`
  - 用途：承载 Apple、Google、匿名继续等继续方式。
  - 状态：`default`、`loading`、`disabled`、`error`。
  - 冻结约束：登录与匿名路径必须同层可见，但主登录动作的强调带宽高于匿名次动作。
- `permission_benefit_card`
  - 用途：解释健康权限收益、读取范围与拒绝后的降级路径。
  - 状态：`default`、`permission_denied`、`platform_unavailable`。
  - 冻结约束：先讲收益再讲范围，不得把权限技术说明放到价值承诺之前。
- `activation_handoff_note`
  - 用途：承载激活完成后的轻确认与进入主应用前的最后说明。
  - 状态：`default`、`success`、`partial_ready`。
  - 冻结约束：只做轻确认，不得升级为庆祝页或额外分流页。

## 全局冻结继承声明

- 本模块无独立风格定义权；页面结构、色义、边框强度、按钮层级、错误与权限语气必须继承全局冻结源。
- Light 主题必须沿用暖纸感背景、浅色卡片、深海松石主色与柔和珊瑚/暖橙风险提示；Dark 主题必须沿用深墨青背景、显式卡片边界与克制提亮主色，不得自行反相。
- 本模块不是品牌故事页，不引入插画系统、沉浸式背景图或强渐变品牌幕布；若运行时省略静态氛围化表现，也必须保留 warm calm、细边框卡片、单主焦点和低刺激节奏。

## 设计冻结卡

- 当前状态：`frozen_for_architecture`
- 必须一致项：
  - 每页只能有一个主动作，不允许双 CTA 同权重竞争。
  - 登录与匿名路径必须同层可见，但视觉优先级主次分明。
  - 健康权限文案必须先解释用户收益，再解释读取范围。
  - 激活路径必须保持“价值理解 -> 继续方式 -> 权限/降级 -> 完成交接”的稳定顺序，不得跳成仅权限配置流程。
  - 成功态只能是轻确认，不得出现庆祝页、奖杯页或强激励文案。
- 允许工程化调整项：
  - 具体页数可因流程整合而减少，但不能牺牲每步单一意图。
  - 辅助说明文案长度可按多语言微调。
  - 登录方式按钮可以按平台能力增减，但匿名路径与主登录路径的相对发现性不能被削弱。
  - 健康授权拒绝后的降级入口可以做成页内按钮或轻卡片，但必须留在当前视野内。
- 平台不可偏离项：
  - 权限请求必须在上下文解释之后触发。
  - 首启推进手势、返回和页面过渡遵守移动端可预期基线。
  - Apple / Google / 健康授权等系统能力说明必须符合真实平台行为，不得使用与系统权限范围不一致的承诺文案。
  - 在登录失败、网络失败、授权失败场景下，恢复动作必须页内可达，不能只依赖 toast。
- Prompt 约束：
  - 禁止做成轮播式营销开屏。
  - 禁止在首启或授权后立即强推会员。
  - 禁止让匿名继续变成不可发现的文本链接。
  - 禁止用医疗感插图、数据面板或连续数字块制造“被监测”体验。
  - 禁止在任何首启页堆叠超过一个高强调卡片。
- 冻结前必须确认：登录路径、匿名路径、健康权限话术、激活完成态语气。

## 视觉系统锚点

- 大标题与单句价值承诺需要足够留白，不堆叠三层以上说明。
- 登录选择页更像“信任选择页”，不是社交登录按钮墙。
- 完成过渡页应使用轻确认而不是庆祝性完成动画。
- 主视觉锚点应落在标题、说明与 1 张轻卡片摘要之间的节奏，而不是依赖 hero 图。
- 所有按钮、说明卡、权限范围卡都使用细边框和轻层次；同屏只允许 1 个主色高强调面。
- 错误、拒绝、降级说明优先使用中性说明卡或柔和风险色点缀，不得使用整块高饱和警报底。

## 模块级视觉约束

- 启动页允许出现品牌字标或极轻状态动效，但时长和存在感都必须服务“稳定等待”，不制造品牌表演。
- 欢迎页与登录页的正文宽度必须可快速扫读，避免变成长段教育文案。
- 健康权限页可使用 1 组收益点 + 1 组读取范围说明，但视觉重点必须落在“你会得到什么”，而不是“系统会读取什么”。
- 完成页不出现多入口分流；只保留进入首页的明确主动作。

## 商业化触点

- 本模块不承接强商业化转化。
- 唯一允许的商业化相关语义是对“登录可支持换机恢复 / 长期同步”的轻量价值说明，且只能作为支撑信息，不可升级为主卡或主 CTA。

## UI/UX 与 Pencil 交接验收

- 首屏 3 秒内必须读懂产品承诺，不出现医疗暗示。
- 登录与匿名路径必须同层可见，不把匿名继续藏成弱可发现入口。
- 授权页必须同时覆盖授权成功、拒绝、平台不可用、无数据四类状态。
- 进入主应用前的最后一步只能有一个主动作。
- 所有首启页面都必须符合“单页单任务”的移动端节奏。
- Light / Dark 两套主题都必须保留暖纸感 / 深墨青基底与显式卡片边界，不能在 dark 模式退化成纯黑工具页。
