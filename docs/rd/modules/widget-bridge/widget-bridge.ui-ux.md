# Widget Bridge UI/UX RD

## 模块目标与目标用户

- 模块目标：让桌面小组件成为睡前闭环的快捷入口，而不是装饰性扩展。
- 目标用户：愿意把 Rhythm 放到桌面的用户、睡前需要快速进入动作的用户。

## 页面范围与导航入口

- 页面范围：小组件引导页、组件主题/说明页、桌面唤起来源语义。
- 导航入口：Onboarding 小组件步骤、我的页小组件入口、桌面小组件点击回流。

## 平台基线

- 平台基线：`ios_hig`
- 说明：引导页、说明页、回流体验和不可用平台降级遵守移动端可读、可触和上下文恢复基线；组件视觉本体与引导页显示层都必须继承全局冻结源，不得演变成炫耀式主题展示或系统教程截图墙。
- 工程落地边界：允许按平台能力区分引导步骤、组件尺寸和回流参数，但引导结构、小组件信息层级与回流语义必须保持同一冻结意图。

## 商业目标

- 主要目标：提高桌面存在感和睡前入口可达性。
- 次要目标：为高级组件样式预留合理商业化空间，但不阻断基础价值。
- 业务闭环要求：用户必须明确知道“把 Rhythm 放到桌面后能立即获得什么”，以及点击后会回到哪个关键动作，而不是只完成一个安装动作。

## 艺术指导

- 产品姿态：`quiet assistant`
- 信息密度：`sparse`
- 视觉温度：`warm calm`
- 去原生重心：`material depth`
- 设计记忆点：组件引导像“把节奏放到桌面上”，不是功能安装教程。
- 模块视觉语气：像把今晚目标折成一张安静的桌面便签，强调一眼可得与一触即回，而不是堆叠多个统计模块。

## 信息层级

- 主焦点区：小组件带来的单一收益
- 次焦点区：添加方式 / 成功后的使用方式
- 支撑区：平台限制、失败说明、高级样式说明
- 主动作：查看添加方式或立即去添加
- 次动作：稍后添加、了解更多
- 层级约束：
  - 引导页先回答“有什么用”，再回答“怎么加”。
  - 组件预览只允许一个主收益语义，不做多个卡片并排比较。
  - 回流后的首屏必须继承组件来源语义，让用户知道当前是从桌面进入。

## 核心用户路径

1. 用户在引导或设置中理解小组件价值。
2. 用户完成添加或至少知道如何稍后添加。
3. 用户从桌面直接查看今晚目标并进入关键动作。

## 状态矩阵

| 状态 | 表现要求 |
| --- | --- |
| 理想 | 桌面展示语义清晰，入口直达关键动作 |
| 空态 | 尚未添加时解释价值，不做功能羞辱 |
| 加载 | 快照更新中不展示明显错误纹理 |
| 错误 | 添加失败、平台不支持、快照刷新失败要有降级说明 |
| 权限 | 平台额外能力受限时说明影响 |
| 部分数据 | 无昨晚结果但有今晚目标时仍能展示核心信息 |
| 禁用 | 非支持平台上只展示说明，不伪造组件能力 |
| 成功 | 添加完成后给出下一步使用方式 |
| 锁定/会员 | 高级小组件样式可预留为高级权益，但基础入口不可锁 |

## 全局冻结继承声明

- 本模块必须严格继承 warm calm、克制、细边框卡片、松石主色和非 dashboard 的全局方向；不允许因为“小组件”主题而扩展出独立视觉子品牌。
- 引导页、说明页和组件预览卡都必须使用全局冻结的表面层级、边框强度、按钮姿态和风险语气；Dark 主题下也必须保持卡片边界可辨，不得做成高对比霓虹桌面牌。
- 运行时如受平台尺寸限制而减少细节，只能删减次级说明，不能改变“今晚目标 / 快速动作 / 轻确认”的核心层级。

## 设计冻结卡

- 当前状态：`needs_user_approval`
- 必须一致项：
  - 小组件价值必须围绕“快速查看今晚目标 / 进入关键动作”。
  - 基础组件不可成为纯付费入口。
  - 平台不支持与添加失败都必须有明确降级说明。
  - 组件快照中的主信息必须保持单焦点，不得同时承载趋势、历史、营销和多种快捷动作。
  - 回流后必须恢复正确上下文，例如进入今日页对应区块或睡前关键动作，而不是落到无语义首页顶层。
- 允许工程化调整项：
  - 不同平台的具体添加步骤文案可以差异化。
  - 组件快照的信息密度可因系统尺寸稍作调整。
  - 预览图可以使用静态示意、真机截图样式或代码生成快照，但视觉层级和信息重点必须一致。
  - 成功后引导可以是页内确认、底部卡片或轻弹层，但不得中断主返回路径。
- 平台不可偏离项：
  - 桌面点击回流必须恢复正确上下文。
  - 引导说明必须符合系统平台的实际添加路径。
  - 不支持的平台必须明确说明边界和替代路径，不能伪造“即将支持”成为默认主动作。
  - 组件刷新失败或数据为空时，快照仍必须展示稳定可读的基础结构，不能出现破碎占位感。
- Prompt 约束：
  - 禁止把小组件做成装饰主题展示页。
  - 禁止基础小组件被会员前置锁定。
  - 禁止回流后丢失入口来源语义。
  - 禁止使用高密度数据块把组件做成微型 dashboard。
  - 禁止引导页变成长步骤教程海报。
- 冻结前必须确认：组件信息密度、桌面点击落点、失败降级说明和高级样式边界。

## 视觉系统锚点

- 引导页用少量信息表达“桌面上能立即得到什么”，不是步骤长教程。
- 组件预览卡需保持大留白和低刺激，不做密集数据块。
- 高级样式若存在，应作为次级示例，不压过基础组件价值。
- 基础组件建议固定为“今晚目标 / 当前状态 / 单一进入动作”三层中的一到两层组合，避免一屏塞满日历、趋势和标签。
- 预览区域与说明区域要形成明显主次，预览是证据，说明是补充，不可反转。
- 失败与不支持状态使用细边框说明卡和中性文案承载，不使用整块错误底色。

## 模块级视觉约束

- 小组件预览卡的背景、边框、文字和强调色必须直接映射主题冻结文件中的 card、text、primary、status 语义角色，不得自行做品牌色变体。
- 小组件内容必须优先展示可一眼理解的短文本和轻量状态，不展示需要滚动理解或多步解码的信息。
- 引导页中的步骤说明最多保留 2-3 个，且每步只承载一个动作，不写成长篇平台教学。
- 从桌面回流后的页内提示如需展示，只能是轻量来源标记或上下文高亮，不能做整页欢迎返回态。

## 商业化触点

- 允许的商业化触点仅限高级组件样式、更多尺寸语义或更深入桌面信息密度的高意图权益展示。
- 基础组件的“查看今晚目标 / 进入关键动作”价值必须完全可用；商业化只能追加深度，不得抽走基础入口。

## UI/UX 与 Pencil 交接验收

- 小组件价值必须绑定“快速查看今晚目标 / 进入睡前动作”，不能只做装饰卡片。
- 失败或平台不支持时要有明确降级说明。
- 桌面点击来源必须能在主应用里恢复正确上下文。
- 基础组件不能成为纯付费前置能力。
- 组件预览和引导页必须能被开发准确映射到可实现快照结构。
- Light / Dark 双主题下，小组件预览都必须保持同一层级与 calm 质感，不能一套温和一套炫技。
