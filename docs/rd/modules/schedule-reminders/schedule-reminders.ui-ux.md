# Schedule Reminders UI/UX RD

## 模块目标与目标用户

- 模块目标：让用户建立目标作息基准，并配置柔性但有效的提醒策略。
- 目标用户：首次设置用户、想调整目标的老用户、时区变化用户、提醒犹豫用户。

## 页面范围与导航入口

- 页面范围：目标设置页、作息设置页、提醒设置页、时区模式页。
- 导航入口：Onboarding 内嵌入口、我的页设置入口、今日页快捷入口。

## 平台基线

- 平台基线：`ios_hig`
- 说明：时间选择、表单交互、底部确认、权限说明和返回路径遵循 iOS 基线；视觉气质必须继承全局冻结源，不得做成系统设置中心、效率工具控制台或表单拼贴页。
- 工程落地边界：允许原生 picker、自定义时间轮或分段选择卡承载时间输入，但实现必须保留单列节奏、主次清晰的卡片层级和 warm calm 的低刺激氛围。

## 商业目标

- 主要目标：帮助用户建立可信目标基准，并愿意开启足够柔和的提醒。
- 次要目标：为后续通知参与率和长期稳定度解释提供统一参照。
- 业务闭环要求：用户离开本模块时，应已经形成可执行的今晚计划，并理解提醒是在“帮助回到节奏”，不是“被监督打卡”。

## 艺术指导

- 产品姿态：`precision tool`
- 信息密度：`balanced`
- 视觉温度：`warm calm`
- 去原生重心：`typography and rhythm` + `material depth`
- 设计记忆点：表单不是设置中心，而是“今晚节奏定义器”。
- 模块视觉语气：像校准个人节奏的安静控制台，只把时间与提醒本身作为主角，不引入额外统计图、徽章或营销插图。

## 信息层级

- 主焦点区：目标入睡与起床时间
- 次焦点区：阈值、一天起始时间、提醒策略
- 支撑区：时区说明、高级模式说明
- 主动作：保存目标与提醒策略
- 次动作：跳过、稍后设置、查看说明
- 层级约束：
  - 首屏只能突出“目标时间”这一层，不把阈值、时区和高级模式拉到同级。
  - 提醒策略是主配置完成后的第二节奏，不得压过目标时间本身。
  - 权限说明是支撑信息，不得先于提醒策略主卡抢占视觉重心。

## 核心用户路径

1. 用户输入目标入睡与起床时间。
2. 用户确认熬夜阈值和一天起始时间。
3. 用户选择柔性提醒策略。
4. 系统保存并更新后续判断与通知调度。

## 状态矩阵

| 状态 | 表现要求 |
| --- | --- |
| 理想 | 默认值合理、一步一意图，完成速度快 |
| 空态 | 首次无配置时，通过推荐值降低决策负担 |
| 加载 | 读取旧配置时显示表单骨架或禁用态 |
| 错误 | 保存失败、时区读取失败、通知权限缺失要有解释与重试 |
| 权限 | 通知权限缺失时说明影响，但允许先保存计划 |
| 部分数据 | 仅部分字段可用时保留已填项，不清空表单 |
| 禁用 | 高级策略未开放时，展示未来能力但不破坏主闭环 |
| 成功 | 保存后给出轻量确认，不弹侵入式成功页 |
| 锁定/会员 | 双目标、轮班、时差高级模式可作为高级能力预留 |

## 全局冻结继承声明

- 本模块必须继承全局的非 dashboard 原则：使用单列卡片流、宽松留白、细边框和克制阴影组织信息，不允许做成多宫格参数面板。
- Light 主题沿用暖白背景、浅表面和深海松石主色；Dark 主题沿用深墨青背景、显式卡片边界和低饱和提亮主色，不得用霓虹色或大面积高对比警示破坏夜间平静感。
- 所有时间、阈值、说明、权限、成功和锁定状态的色义都必须映射到全局冻结与主题冻结文件，不得为局部页面重定义品牌色或风险色。

## 设计冻结卡

- 当前状态：`needs_user_approval`
- 必须一致项：
  - 时间设置必须比传统设置页更轻，视觉焦点明确落在目标本身。
  - 提醒文案强调帮助回到节奏，不使用强监督语言。
  - 高级模式只作为次级增强，不破坏基础表单完成率。
  - “目标时间 -> 提醒策略 -> 权限补充说明” 的阅读顺序必须稳定，不得把通知授权前置成第一任务。
  - 保存成功只能轻量确认，不跳转到夸张成功页。
- 允许工程化调整项：
  - 时间输入控件可以用原生 picker 或定制选择器，但层级和文案语义必须一致。
  - 时区说明可以以卡片或行内说明实现。
  - 高级模式入口可以是说明卡、次级列表项或锁定卡，但必须位于主配置完成区之后。
  - 当字段较多时，可以拆成 2 个连续页面或 1 个长页分区，但每屏只允许一个明确主任务。
- 平台不可偏离项：
  - 时间选择与通知权限触发遵守平台可预期交互。
  - 保存动作与返回路径保持清晰，不隐藏在手势后。
  - 时区变化与通知不可用必须基于真实系统能力做说明，不得伪造后台能力或静默补偿承诺。
  - 保存失败后必须保留用户已填数据，不能因为重试而清空表单。
- Prompt 约束：
  - 禁止做成复杂设置中心。
  - 禁止把高级策略做成过早营销阻塞。
  - 禁止把提醒页写成“打卡监督”语气。
  - 禁止引入图表、周报、统计块等与当前主任务无关的模块。
  - 禁止使用高饱和红橙大面积强调“晚睡风险”。
- 冻结前必须确认：默认值策略、提醒话术、时区切换说明、高级策略锁定语义。

## 视觉系统锚点

- 时间数字是视觉主信息，辅助字段必须明显降级。
- 提醒策略卡片应比系统表单更有呼吸感，但不能装饰过度。
- 时区变化说明应以轻解释卡承载，而不是突兀弹窗。
- 目标时间区域允许使用 1 个高强调主卡或 2 个配对时间面，但必须保持同一视觉组。
- 阈值、一天起始时间与提醒节奏使用次级卡片或列表块承载，边框与间距统一，不做不同风格拼盘。
- 保存区必须稳定停留在视线收束位置，既可单手触达，也不会与次要入口竞争。

## 模块级视觉约束

- 数字时间要有轻重量和宽呼吸感，避免粗黑数字形成闹钟式压迫。
- 通知提醒策略可使用轻量单选卡或分段卡，但每个选项只表达一个清晰语义，不堆叠多行技术说明。
- 时区变化说明卡必须优先回答“为什么你看到这个”和“当前设置会受什么影响”，再提供调整动作。
- 锁定或高级模式如果展示预览，只能占次焦点层级，不能压过免费基础设置。

## 商业化触点

- 可承接的商业化触点仅限高级作息模式、高级提醒策略或跨时区深度适配等高意图能力。
- 商业化入口必须出现在主配置完成之后，且以“更深入优化节奏”为叙事，不得以“不开会员就无法设置提醒”施压。

## UI/UX 与 Pencil 交接验收

- 时间选择不能像复杂设置中心，必须围绕“建立今晚目标”表达。
- 提醒策略页不使用强监督或羞辱式文案。
- 时区变化时必须优先解释影响，而不是直接要求重填所有设置。
- 高级能力入口不能干扰免费主配置完成。
- 默认值与推荐文案必须让首次完成速度足够快。
- Dark 主题下卡片边界、输入框和时间主信息仍必须清晰可分，不得糊成一层深色面。
