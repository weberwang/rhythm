# bedtime_notifications UI/UX RD

> 配对实现 RD：`docs/rd/modules/bedtime_notifications/bedtime_notifications.impl.md`
> 全局基线：`docs/rd/2026-06-02-rhythm-commercial-global-rd.md`
> 工作流状态：`modules_split`

## 1. 模块目标

让用户在睡前以低打扰方式进入“准备睡了”状态，选择今晚状态并获得一个轻量收尾动作。

## 2. 目标用户

晚上到点仍在拖延、需要柔性提醒和低刺激执行页的用户。

## 3. 页面范围与导航入口

- 睡前页
- 提醒策略设置页
- 提醒设置编辑页
- 通知补救反馈
- 睡前状态选择和动作建议区

## 4. 核心用户路径

1. 用户收到柔性提醒或点击小组件。
2. 用户进入睡前页。
3. 用户看到距离目标入睡的时间差。
4. 用户选择今晚状态。
5. 系统给出一个动作建议。
6. 用户退出 App，等待次日反馈。

## 5. 状态矩阵

| 状态 | 设计要求 |
| --- | --- |
| ideal | 深色低刺激，倒计时为主焦点 |
| loading | 获取目标或提醒状态时保持安静 |
| error | 提醒调度失败给轻提示 |
| permission | 通知权限不足时给补救入口 |
| partial data | 无睡眠数据不阻断睡前模式 |
| disabled | 无目标时引导设置目标 |
| success | 状态选择后给平静反馈 |
| locked | 基础睡前模式不付费 |

## 6. 设计来源

核对 Pencil 睡前页、提醒设置页、弹层与反馈组件。深色页面不能简单复用浅色壳。

## 7. 设计冻结卡

- 必须保持：低刺激、最多一个主动作、路径不超过 3 次点击。
- 可工程化调整：倒计时动效和状态卡布局。
- 不可偏离：不得把睡前页做成任务打卡或高压提醒页。

## 8. 验收门槛

- 通知、小组件、今日页都能进入睡前路径。
- 无目标时不出现错误死路。
- 提醒失败不阻断 onboarding 完成。
- 文案不命令、不羞辱。
