# activation_onboarding UI/UX RD

> 配对实现 RD：`docs/rd/modules/activation_onboarding/activation_onboarding.impl.md`
> 全局基线：`docs/rd/2026-06-02-rhythm-commercial-global-rd.md`
> 工作流状态：`modules_split`

## 1. 模块目标

把首次激活设计成商业级漏斗，让用户在 2 分钟内理解产品价值、建立数据信任、完成目标设置前置动作，并进入可用状态。

## 2. 目标用户

首次安装 Rhythm 的晚睡用户，尤其是对健康数据授权、登录、提醒打扰和付费弹窗敏感的用户。

## 3. 页面范围与导航入口

- 欢迎价值页
- 登录选择页
- 睡眠数据授权页
- 完成过渡页

目标设置、提醒策略和小组件引导分别由 `goal_schedule`、`bedtime_notifications`、`widget_presence` 承接，但在引导流中联动。

## 4. 核心用户路径

1. 用户看到“今晚轻一点回到节奏”的价值承诺。
2. 用户选择登录或匿名继续。
3. 用户授权健康数据，或选择手动记录。
4. 用户完成目标和提醒设置。
5. 用户看到完成过渡并进入今日页。

## 5. 状态矩阵

| 状态 | 设计要求 |
| --- | --- |
| ideal | 主路径清晰，单主动作推进 |
| loading | 登录或权限请求显示轻等待 |
| error | 登录失败、授权失败给出降级路径 |
| permission | 明确读取什么、不读取什么、用户得到什么 |
| partial data | 权限成功但无数据时说明可能延迟 |
| disabled | 平台能力不可用时允许手动模式 |
| success | 完成后进入今日，不强推付费 |
| locked | onboarding 内不出现付费锁定 |

## 6. 设计来源

进入设计阶段前核对 Pencil 中欢迎、登录、健康授权和完成过渡页面。若现有 Pencil 缺少完成过渡页，需要先补设计缺口。

## 7. 设计冻结卡

- 必须保持：价值承诺、信任说明、手动降级、无付费打断。
- 可工程化调整：登录按钮排列、隐私说明承载形式。
- 不可偏离：不得把 onboarding 做成纯品牌宣传页或强制登录页。

## 8. 验收门槛

- 3 秒内读懂产品不是普通睡眠报告。
- 每页只有一个主动作。
- 健康授权失败仍能继续。
- 完成后自然进入今日页。
- 所有用户可见文案接入国际化。
