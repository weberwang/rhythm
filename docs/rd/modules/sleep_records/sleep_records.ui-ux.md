# sleep_records UI/UX RD

> 配对实现 RD：`docs/rd/modules/sleep_records/sleep_records.impl.md`
> 全局基线：`docs/rd/2026-06-02-rhythm-commercial-global-rd.md`
> 工作流状态：`modules_split`

## 1. 模块目标

让用户可靠接入、补录和修正睡眠记录，并理解数据来源和可信状态。

## 2. 目标用户

授权健康数据的用户、授权失败用户、数据缺失用户，以及需要手动修正记录的用户。

## 3. 页面范围与导航入口

- 健康数据接入页
- 手动补录页
- 记录编辑页
- 数据来源说明弹层
- 权限补救对话框

## 4. 核心用户路径

1. 用户授权健康数据或选择手动模式。
2. 系统同步最近记录。
3. 数据缺失或失败时，用户进入手动补录。
4. 用户修正记录后，下游页面使用有效记录。

## 5. 状态矩阵

| 状态 | 设计要求 |
| --- | --- |
| ideal | 展示最近同步结果和来源 |
| loading | 同步中显示进度感和可退出 |
| error | 区分权限、平台、读取、网络问题 |
| permission | 提供去授权、继续手动、稍后处理 |
| partial data | 解释数据延迟和可信度 |
| disabled | 平台不可用时不阻断使用 |
| success | 补录或修正后轻反馈 |
| locked | 基础补录不付费，高级历史可后续承接 |

## 6. 设计来源

核对 Pencil 中健康授权、数据接入、手动补录、数据来源说明和权限补救弹层。

## 7. 设计冻结卡

- 必须保持：自动记录可解释、手动路径一等、来源可见。
- 可工程化调整：补录表单具体控件和同步状态细节。
- 不可偏离：不得让用户卡在授权失败页。

## 8. 验收门槛

- 授权失败仍可完成闭环。
- 同步失败有重试和补录。
- 用户修正不会被视觉上误认为系统原始记录。
- 数据来源说明可被找到。
