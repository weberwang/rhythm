# analytics_release UI/UX RD

> 配对实现 RD：`docs/rd/modules/analytics_release/analytics_release.impl.md`
> 全局基线：`docs/rd/2026-06-02-rhythm-commercial-global-rd.md`
> 工作流状态：`modules_split`

## 1. 模块目标

定义发布前后所有用户可见的反馈、埋点确认面和人工验收入口，保证产品闭环能被验证。

## 2. 目标用户

主要服务内部产品、设计、研发和运营。对终端用户只体现为更稳定的错误提示、轻反馈和发布质量。

## 3. 页面范围与导航入口

本模块无独立用户主页面，覆盖：

- 全局轻提示
- 错误反馈
- 发布前人工验收清单
- 内测路径说明
- 埋点字典与漏斗核对

## 4. 核心使用路径

1. 研发按模块完成实现。
2. 运行测试和埋点核对。
3. 产品验收激活、行为、复盘和付费漏斗。
4. 发布前确认风险、回滚和禁用策略。

## 5. 状态矩阵

| 状态 | 设计要求 |
| --- | --- |
| ideal | 关键反馈轻量且一致 |
| loading | 全局加载不阻断阅读 |
| error | 错误提示可行动 |
| permission | 权限失败提示可恢复 |
| partial data | 部分数据说明清楚 |
| disabled | 功能关闭说明原因 |
| success | 成功提示克制 |
| locked | 付费锁定提示可解释 |

## 6. 设计来源

核对 Pencil 弹层、对话框、轻提示横幅和错误状态。若没有专门节点，继承 `app_foundation` 的反馈组件。

## 7. 设计冻结卡

- 必须保持：反馈可行动、轻提示一致、错误不制造恐慌。
- 可工程化调整：发布清单呈现形式。
- 不可偏离：不得把埋点或调试信息暴露给普通用户。

## 8. 验收门槛

- 每个关键漏斗事件有触发页面。
- 发布前清单可执行。
- 错误反馈不泄露敏感数据。
- 内测路径可以被端到端走查。
