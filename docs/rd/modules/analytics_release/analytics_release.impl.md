# analytics_release 实现 RD

> 配对 UI/UX RD：`docs/rd/modules/analytics_release/analytics_release.ui-ux.md`
> 全局基线：`docs/rd/2026-06-02-rhythm-commercial-global-rd.md`
> 工作流状态：`modules_split`

## 1. 业务能力与边界

负责统一埋点网关、事件字典、发布清单、内测走查和质量门槛。不负责各业务模块内部逻辑。

## 2. 继承包栈

- 当前先使用项目内部 `AnalyticsGateway`
- 如后续确认生产需求，再评估 Crash 监控、远程配置和 A/B SDK

## 3. 领域模型

- `AnalyticsEvent`
- `ReleaseChecklist`
- `FunnelMetric`
- `QualityGate`

## 4. 应用状态

无常规页面状态。需要记录：

- 事件触发
- 事件参数合法性
- 发布前检查结果
- 内测走查状态

## 5. 基础设施边界

- 分析网关为可替换接口。
- 业务模块只调用事件抽象，不直接依赖生产 SDK。
- 远程配置若引入，必须有本地默认值和关闭策略。

## 6. 数据与安全

- 埋点禁止上传原始睡眠时间、健康来源主键、令牌和个人敏感信息。
- 事件参数只记录状态、来源、类别和漏斗节点。

## 7. 埋点范围

覆盖：

- 激活漏斗
- 行为闭环
- 反馈复盘
- 商业化
- 信任与隐私
- 发布质量

## 8. 测试范围

- 事件名称合法性
- 参数脱敏
- 关键事件触发
- 发布清单完整性
- 内测端到端路径

## 9. 实现约束

不得在业务页面散落字符串事件名。事件名需要集中定义，并由测试覆盖关键漏斗。
