# Insights Recovery UI/UX RD

## 模块目标与目标用户

- 模块目标：把零散日常行为聚合成可行动复盘，并承接高级恢复和付费价值。
- 目标用户：持续回访用户、明显晚睡后的用户、评估订阅价值的用户。

## 页面范围与导航入口

- 页面范围：洞察页、周报详情、恢复计划详情、报告历史。
- 导航入口：主导航洞察页、今日页恢复卡、日历历史入口、会员承接入口。

## 平台基线

- 平台基线：`ios_hig`
- 说明：滚动卡片流、统计块层级、次级详情跳转和付费承接都遵循 iOS 基线，视觉表达继承全局冻结源。

## 商业目标

- 主要目标：把周报、稳定度和恢复建议变成持续回访与订阅转化的关键时刻。
- 次要目标：在不制造压力的前提下，让用户读懂“为什么值得继续回来”。

## 艺术指导

- 产品姿态：`quiet assistant`
- 信息密度：`balanced`
- 视觉温度：`warm calm`
- 去原生重心：`material depth`
- 设计记忆点：大比例达标率摘要 + 轻解释卡 + 暖色高级洞察入口的层级递进。

## 信息层级

- 主焦点区：本周达标率 / 稳定度摘要
- 次焦点区：原因分布与恢复建议
- 支撑区：高级洞察入口、历史报告入口
- 主动作：查看当前最有价值的解释或恢复建议
- 次动作：深入了解、打开历史、进入升级详情

## 核心用户路径

1. 用户查看本周达标率和稳定度摘要。
2. 用户理解主要晚睡原因与恢复建议。
3. 用户查看周报详情或历史报告。
4. 用户在高意图场景下进入高级解释或订阅。

## 状态矩阵

| 状态 | 表现要求 |
| --- | --- |
| 理想 | 每个图表旁都有一句可行动结论 |
| 空态 | 数据不足时解释“先积累几天记录再回来” |
| 加载 | 周报聚合加载不阻塞整页摘要 |
| 错误 | 报告生成失败或拉取失败要可重试 |
| 权限 | 无记录时说明依赖数据来源而不是空白图表 |
| 部分数据 | 记录天数不足时，允许展示轻量结论而不是强评分 |
| 禁用 | 高级解释未开放时展示升级理由 |
| 成功 | 明显晚睡时优先展示恢复建议而非惩罚反馈 |
| 锁定/会员 | 恢复计划详情、稳定度解释、历史报告可作为高级边界 |

## 模块级组件冻结骨架

- `weekly_insight_hero_card`
  - 用途：承载本周达标率、稳定度摘要和单句核心结论。
  - 状态：`default`、`low_data`、`warning`、`loading`。
  - 冻结约束：必须先给可理解结果，再展示更深入口，不得让商业触点先占首焦点。
- `stability_explainer_panel`
  - 用途：承载稳定度解释、趋势摘要和轻量下一步。
  - 状态：`default`、`partial_data`、`locked_detail`。
  - 冻结约束：每块解释旁必须有一句行动型说明，不能只剩抽象数字。
- `cause_distribution_card`
  - 用途：承载主要原因分布与相应解释。
  - 状态：`default`、`empty`、`partial_data`。
  - 冻结约束：图表只是辅助解释，不得做成复杂数据仪表盘。
- `recovery_plan_card`
  - 用途：承载恢复建议摘要、详情入口和高级承接。
  - 状态：`default`、`high_priority`、`locked`。
  - 冻结约束：恢复建议优先于付费卡呈现，付费只做次级收尾承接。

## 设计冻结卡

- 当前状态：`frozen_for_architecture`
- 必须一致项：
  - 洞察页必须先给“已可理解的结果”，再给升级入口。
  - 高级洞察入口只能作为次级暖色强调块，不可压过主摘要。
  - 每个统计块旁边都要保留一句可行动解释。
- 允许工程化调整项：
  - 统计块字段可按真实数据量轻微压缩或换行。
  - 暖色升级卡内部说明可按定价策略调整。
- 平台不可偏离项：
  - 洞察卡片点击区和阅读顺序必须保持单手可扫读。
  - 付费承接不能以强模态拦截首屏主内容。
- Prompt 约束：
  - 禁止把洞察页做成复杂商业仪表盘。
  - 禁止把恢复建议视觉化成危机警报。
  - 禁止用付费卡片抢占首焦点。
- 冻结前必须确认：免费摘要范围、付费承接时机、恢复建议呈现层级、图表解释语气。

## 视觉系统锚点

- 首个摘要卡必须拥有最大读数权重，但整体仍保持轻盈。
- 解释卡、原因列表和恢复总结卡必须使用统一卡片边界和留白节奏。
- 高级洞察入口允许使用暖珊瑚系轻强调，但只作为商业触点收尾。

## 商业化触点

- 更深层稳定度解释
- 高级恢复建议详情
- 历史报告与更长期趋势

## UI/UX 与 Pencil 交接验收

- 洞察页不能做成复杂数据仪表盘。
- 恢复建议必须在明显晚睡后可被快速看到。
- 付费墙只能出现在高意图动作之后，不可在首屏硬拦截。
- 周报摘要、稳定度、原因分布必须共用同一文案语气。
- 已批准预览中的“摘要 -> 解释 -> 原因 -> 恢复 -> 高级入口”顺序不得被改写。
