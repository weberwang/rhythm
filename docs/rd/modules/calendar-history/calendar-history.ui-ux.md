# Calendar History UI/UX RD

## 模块目标与目标用户

- 模块目标：把长期作息结果转成可读、可回看、可解释的历史反馈。
- 目标用户：想看近 7-30 天趋势的用户、需要回看某天异常的用户、正在评估长期价值的用户。

## 页面范围与导航入口

- 页面范围：日历页、热力图、筛选控件、单日详情弹层。
- 导航入口：主导航日历页、今日页趋势卡、洞察页链接。

## 平台基线

- 平台基线：`ios_hig`
- 说明：月历滚动、筛选切换、单日详情弹层与底部导航遵循 iOS 基线，视觉系统继承全局冻结源。

## 商业目标

- 主要目标：建立长期趋势可视化信任，让免费层价值足够成立。
- 次要目标：为更长历史和高级筛选提供自然升级边界。

## 艺术指导

- 产品姿态：`precision tool`
- 信息密度：`balanced`
- 视觉温度：`warm calm`
- 去原生重心：`material depth`
- 设计记忆点：圆点式热力日历 + 轻摘要卡 + 单日详情的纸感记录体验。

## 信息层级

- 主焦点区：当前月热力图
- 次焦点区：月度摘要
- 支撑区：单日详情、筛选图例、编辑目标入口
- 主动作：查看某一天或理解本月趋势
- 次动作：切换筛选、编辑目标

## 核心用户路径

1. 用户进入日历页查看月度表现。
2. 用户切换筛选模式理解不同趋势。
3. 用户点击某天查看详情与原因。
4. 用户必要时进入高级历史或洞察入口。

## 状态矩阵

| 状态 | 表现要求 |
| --- | --- |
| 理想 | 热力图基于目标偏移清晰表达趋势 |
| 空态 | 无记录时展示如何补录和如何开始 |
| 加载 | 月度聚合加载可局部骨架 |
| 错误 | 聚合失败、筛选异常要可重试 |
| 权限 | 无健康数据时说明“仍可用手动记录建立历史” |
| 部分数据 | 缺失数据日必须明确显示为未记录 |
| 禁用 | 高级历史未开放时，保留免费边界说明 |
| 成功 | 单日详情能解释结论，不只展示数字 |
| 锁定/会员 | 30 天以前历史或高级筛选可作为付费边界 |

## 模块级组件冻结骨架

- `monthly_heatmap_panel`
  - 用途：承载月度热力图与颜色图例。
  - 状态：`default`、`loading`、`empty`、`locked_history_tail`。
  - 冻结约束：热力单元必须围绕相对目标偏移表达，不得退化成厚重统计色块。
- `history_filter_chip_bar`
  - 用途：承载筛选维度切换与当前视角说明。
  - 状态：`default`、`selected`、`disabled`。
  - 冻结约束：筛选只是解释方式，不得压过月历主焦点。
- `day_detail_summary_card`
  - 用途：承载单日偏移、来源、原因和回看说明。
  - 状态：`default`、`partial_data`、`missing_record`、`locked`。
  - 冻结约束：详情卡是月历的次级解释层，不能升级成第二个首页式主英雄卡。
- `history_lock_note_card`
  - 用途：承载免费/高级历史边界与升级说明。
  - 状态：`default`、`locked`、`upsell`。
  - 冻结约束：锁定说明必须明显晚于免费可用内容出现，不覆盖主月历可读性。

## 设计冻结卡

- 当前状态：`frozen_for_architecture`
- 必须一致项：
  - 热力圆点颜色必须相对目标时间偏移，而不是绝对睡觉时钟。
  - 日历本体是主焦点，月摘要和单日详情必须退居二级。
  - “无数据”必须保持浅中性占位，不与锁定历史混淆。
- 允许工程化调整项：
  - 日历单元大小和横向间距可按设备宽度轻微自适应。
  - 摘要卡的字段顺序可按真实数据长度微调。
- 平台不可偏离项：
  - 单日详情的展开方式必须符合移动端手指点击与阅读节奏。
  - 筛选控件不可牺牲可点击尺寸和清晰度。
- Prompt 约束：
  - 禁止把日历页做成财务图表面板。
  - 禁止用过深对比和重边框破坏纸感轻度。
  - 禁止锁定态覆盖主月历可读性。
- 冻结前必须确认：热力图颜色语义、单日详情层级、锁定边界位置。

## 视觉系统锚点

- 圆点热力单元必须保持轻量、均匀、可扫读，不演化成厚重色块。
- 月摘要卡用白卡 + 细边框承托，不抢热力图主角位置。
- 单日详情使用更细的文本层级，不把详情面板做成第二个首页。

## UI/UX 与 Pencil 交接验收

- 热力图颜色必须相对目标时间，而不是绝对时间。
- 单日详情必须包含来源、偏移和原因入口。
- 未记录、部分记录、锁定历史三类状态不能混淆。
- 页面不能做成医学监测面板。
- 已确认预览中的“热力图主焦点 + 轻摘要卡 + 单日详情”骨架不得被重排成多列 dashboard。
