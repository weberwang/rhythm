# sleep-data-core UI/UX RD

> 产物类型：`module_uiux_rd`
> 模块：`sleep-data-core`
> 文档成熟度：`split_draft`
> 日期：`2026-06-08`

## 1. 模块目标与目标用户

该模块虽不是独立顶层页面，但它负责所有“结果是否可信、目标是否存在、提醒是否可执行、恢复是否有依据”的核心体验基础。  
目标用户是所有会接触睡眠记录、目标作息、手动补录、修正、恢复计划和提醒反馈的用户。

## 2. 页面范围与导航入口

- 无独立顶层导航页
- 通过以下承载面暴露：
  - 今日页的记录来源与修正入口
  - 日历页的单日详情与补录入口
  - 睡前页的目标时间与提醒语义
  - 洞察页的恢复基础信息
  - 我的页的权限与同步状态
- 导航入口：
  - 来自上层 feature 的表单、弹层、详情页内入口

## 3. 核心用户路径

1. 系统读取健康数据或接收手动补录。
2. 用户看到记录来源、可信状态与偏移结果。
3. 若数据缺失、延迟或不准确，用户进入补录或修正路径。
4. 系统据此重新计算目标偏移、提醒计划和恢复建议基础。
5. 下游页面消费统一结果，不各自拼口径。

## 4. 状态矩阵

| 状态 | 触发条件 | 承载位置 | 设计处理 |
| --- | --- | --- | --- |
| ideal | 自动数据完整且可信 | Today / Calendar / Insights | 展示来源与结果 |
| loading | 读取健康数据或重算中 | 下游页面骨架位 | 不假装已有最终结果 |
| empty | 无记录 | Today / Calendar | 明确未记录并提供补录路径 |
| error | 读取失败或写入失败 | 下游页内提示 | 允许重试与继续本地闭环 |
| permission | 健康权限未授权 | Today / Profile / 授权解释位 | 解释价值并提供手动路径 |
| partial_data | 数据延迟或缺字段 | Today / Calendar | 说明当前判断不完整 |
| disabled | 某能力暂不可用 | 表单/操作入口 | 解释影响，不阻断其他能力 |
| success | 手动修正或补录完成 | Today / Calendar 详情 | 标记来源已变更 |

## 5. 结构语义

- `scroll_model`: `mixed`
- `list_model`: `repeated_list`
- `overlay_model`: `modal_layer + badge_overlay`
- `layout_model`: `mixed`
- `sticky_model`: `none`
- `component_repeatability`: 来源标签、可信提示、补录表单、修正表单、同步状态横幅、权限说明卡

## 6. 模块级非页面组件设计骨架

| 组件 | 用途范围 | 状态/变体 | 复用边界 | 后续是否进入模块设计源冻结 |
| --- | --- | --- | --- | --- |
| 记录来源标签 | 自动/手动/修正来源说明 | 自动、手动、已修正 | Today / Calendar / Insights | 是 |
| 可信度提示条 | 解释数据是否完整 | 正常、延迟、部分数据 | 结果型页面共享 | 是 |
| 手动补录表单 | 快速补录缺失记录 | 默认、校验、提交中 | Today / Calendar | 是 |
| 手动修正表单 | 修正自动记录 | 默认、已变更、冲突提醒 | Today / Calendar | 是 |
| 同步与权限状态横幅 | 权限/同步说明 | 信息、警示、错误 | Today / Profile | 是 |

## 7. 设计源

- 共享冻结上游：
  - `docs/rd/global-design-guidelines.md`
  - `docs/rd/pencil-design-source-packet.md`
- 页面证据：
  - Today / Calendar / Insights / Profile 对应 Pencil 页面为主要承载参考
- 设计约束：
  - 状态提示必须帮助恢复，不制造失败感
  - 数据来源与可信状态不能只靠颜色表达
- 模块阶段默认不生成新预览

## 8. 设计冻结卡

- `freeze_status`: `reserved`
- `module_component_freeze`: `reserved`
- `high_fidelity_focus`: 来源标签、手动补录入口、部分数据解释、同步/权限提示
- `immutable_constraints`:
  - 自动数据被手动修正后必须保留来源可解释性
  - 权限失败不应阻断主闭环
- `adjustable_items`:
  - 表单展开方式
  - 提示条在各页中的具体位置

## 9. 验收门

- UI/UX：
  - 用户能理解当前数据是否可信
  - 手动补录和修正路径足够快
- 模块设计冻结：
  - 状态提示语义清晰
  - 来源与修正语义统一
- 代码交接：
  - 数据来源、修正、同步、权限的状态口径统一

## 10. 开放问题

- 轮班/时差策略是否首发落入本模块，需要后续范围确认。
- 自动数据延迟的可接受窗口需要在实现前进一步量化。
