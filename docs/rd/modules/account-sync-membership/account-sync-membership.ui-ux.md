# Account Sync Membership UI/UX RD

## 模块冻结定位

- 模块定位：`Account Sync Membership` 是 Rhythm 的个人控制中心，负责承接账号、同步、恢复购买、会员价值与隐私数据管理。
- 冻结状态：`needs_user_approval`
- 设计源继承：
  - 强制继承 [docs/rd/global-design-guidelines.md](D:/Projects/Flutter/rhythm/docs/rd/global-design-guidelines.md) 的 `design_position`、`global_experience_principles`、`content_and_copy_principles`、`visual_system_rules`、`design_prohibitions`。
  - 强制继承 [docs/rd/light-theme-freeze.yaml](D:/Projects/Flutter/rhythm/docs/rd/light-theme-freeze.yaml) 与 [docs/rd/dark-theme-freeze.yaml](D:/Projects/Flutter/rhythm/docs/rd/dark-theme-freeze.yaml) 的卡片、按钮、状态色和边框规则。
  - 本模块必须严格延续全局冻结方向：`warm calm`、克制、细边框卡片、松石主色、非 dashboard；它是安静的高信任控制中心，不是设置列表拼装页，也不是营销页。

## 模块目标与目标用户

- 模块目标：让用户对账号、同步、恢复、付费与隐私产生稳定信任，并清楚知道当前最重要的管理动作。
- 目标用户：
  - 准备登录或刚登录的用户
  - 需要换机恢复或恢复购买的用户
  - 遇到同步失败或账号异常的用户
  - 正在评估会员价值的用户

## 页面范围与导航入口

- 页面范围：我的页、账号同步页、会员页、付费墙、隐私与数据管理页。
- 导航入口：
  - 主导航“我的”
  - 今日页或洞察页中的升级触点
  - 引导登录入口
  - 同步异常回流入口

## 平台基线

- 平台基线：`ios_hig`
- 平台说明：
  - 账户管理、恢复购买、删除数据、退出登录等高风险操作遵循 iOS 分层与确认模式。
  - 列表行触达区、卡片滚动节奏、弹层说明、错误恢复路径遵循可读性与可触达性基线。
  - 视觉系统不回退成原生设置页直排列表，必须保留产品化卡片结构与层级。

## 商业目标

- 主要商业目标：建立账号、同步、付费、隐私四类高信任入口，降低因“不确定数据是否安全”带来的流失。
- 次级商业目标：在不破坏温和品牌气质的前提下，让用户理解会员对“持续改善、跨设备恢复、长期洞察”的真实价值。
- 商业成功信号：
  - 用户先看懂账号/同步状态，再考虑会员价值。
  - 同步失败时用户仍相信本地数据与恢复路径可控。
  - 匿名用户不会被羞辱式推向注册。

## 艺术指导

- 产品姿态：`quiet assistant`
- 信息密度：`balanced`
- 视觉温度：`warm calm`
- 视觉语气：高信任、低压力、轻管理感、非销售压迫
- 页面记忆点：`账号/同步摘要主卡 + 会员价值次卡 + 隐私/数据管理分组` 的个人控制中心结构，而不是无限长列表。
- 风格限制：
  - 不得做成默认 iOS 设置页拼装。
  - 不得让会员卡成为首屏最强视觉块。
  - 不得把隐私/删除数据入口藏到低发现层级。

## 信息层级

- 一级信息：
  - 账号状态
  - 同步状态
  - 当前最关键的恢复动作
- 二级信息：
  - 会员状态
  - 升级价值摘要
- 三级信息：
  - 隐私与数据管理
  - 数据接入与偏好入口
  - 恢复购买、帮助说明
- 四级信息：
  - 次级说明页
  - 辅助诊断入口
- 固定阅读顺序：
  1. 当前身份与同步状态
  2. 当下最关键动作
  3. 会员价值或权益状态
  4. 隐私与数据管理入口

## 核心用户路径

1. 用户进入“我的”页，先看到账号与同步摘要。
2. 用户必要时执行登录、恢复同步或恢复购买。
3. 用户查看会员状态与升级价值。
4. 用户进入隐私或数据管理页面执行导出、删除、说明阅读等动作。

## 状态矩阵

| 状态 | 表现要求 |
| --- | --- |
| 理想 | 账号、同步、会员、隐私入口分层清晰，首屏可快速扫描 |
| 空态 | 未登录时解释登录收益，但不否定匿名使用价值 |
| 加载 | 会员状态、同步状态、账号信息局部加载，禁止整页空白等待 |
| 错误 | 登录失败、同步失败、恢复购买失败都必须有页内恢复路径 |
| 权限 | 数据导出、删除、账号操作前明确说明影响与确认 |
| 部分数据 | 本地可用但云端未连接时，明确“本地仍可使用” |
| 禁用 | 平台不支持某登录方式或某恢复能力时说明边界，不制造死路 |
| 成功 | 登录、恢复购买、同步完成后给轻量确认，不弹庆祝式成功页 |
| 锁定/会员 | 会员权益说明强调长期改善价值，而不是功能清单堆砌 |

## 设计源与模块继承合同

- Pencil 来源：当前冻结以全局设计源为唯一基准；若后续 Pencil 设计稿出现更强营销导向或更重设置页样式，应视为偏离冻结，需要重新评审。
- 全局继承重点：
  - 继承“锁定内容必须明显晚于已可用内容出现”的原则，因此账号/同步必须优先于会员营销。
  - 继承“帮助文案优先回答为什么会看到这个、现在该做什么”的原则，因此同步失败、匿名态、隐私风险都必须是解释型文案。
  - 继承“卡片是全局主结构单元”的原则，因此首屏以摘要卡和分组卡组织，不用纯列表堆叠。
- 主题继承重点：
  - 会员卡允许用暖色强调，但不得突破主题冻结中“不要让 premium 卡比当前 primary action 更强”的约束。
  - Dark 模式下必须保留卡片边界和分组分层，不能黑底长列表化。

## 设计冻结卡

- 当前状态：`needs_user_approval`
- 必须一致项：
  - 账号/同步信任入口始终优先于会员营销入口。
  - 匿名用户不可被羞辱式驱赶登录，必须保留“本地仍可使用”的稳定叙事。
  - 同步失败时必须同时告诉用户“本地数据状态”“云端状态”“下一步怎么恢复”。
  - 会员价值必须围绕持续改善、换机恢复、长期洞察，而不是只列功能名录。
  - 隐私、导出、删除、退出登录必须在可发现路径中，不能藏进深层设置。
- 允许工程化调整项：
  - 同层级入口顺序可随真实业务权重微调，但账号/同步分组不得下沉。
  - 会员卡中的数据点、权益摘要可随真实方案调整，但语气和层级不得变。
  - 我的页可采用卡片分组或轻列表分组，只要保持摘要主卡优先。
- 平台不可偏离项：
  - 删除、退出登录、恢复购买必须走确认层。
  - 列表行、卡片、按钮必须满足平台触达与无障碍可读基线。
  - 敏感操作结果不能只靠短暂 toast，必须有可感知的结果确认。
- Prompt 约束：
  - 禁止做成默认 iOS 设置页拼装。
  - 禁止会员卡片压过账号与同步主信息。
  - 禁止把隐私入口或删除入口藏到低发现路径。
  - 禁止通过焦虑式文案推动登录或订阅。

## 视觉系统锚点

- 我的页首屏结构：
  - 以 `1` 个账号/同步摘要主卡作为主焦点。
  - 下方接 `2-3` 个分组区，分别承载会员价值、数据管理、隐私/帮助。
- 会员价值卡：
  - 允许使用暖色强调或更高一级的辅助底色，但对比度和视觉权重必须弱于账号/同步主卡。
  - 文案重在价值总结，不做大段促销口号。
- 同步与错误反馈：
  - 以可信中性语气的说明卡承载，不做大红警报横幅。
  - 错误状态必须保留修复动作按钮和当前状态解释的并置关系。
- 模块级视觉约束：
  - 首屏高强调面上限为 `1`，不得形成“主卡 + 促销卡”双英雄竞争。
  - 隐私和风险操作视觉上必须比会员营销更稳重、更清晰。
  - 长列表必须通过分组卡与留白分节，不能退化为单纯设置清单。

## 商业化触点

- 合理商业化触点：
  - 会员状态摘要卡
  - 会员页价值总结卡
  - 付费墙中的长期洞察、恢复计划、跨设备恢复说明
  - 恢复购买入口
- 商业化呈现规则：
  - 先建立账号与数据安全信任，再解释升级价值。
  - 价值叙事围绕“持续改善、历史连续性、换机恢复、深层理解自己”。
  - 不允许用“你当前用不了核心功能”作为默认销售话术。

## UI/UX 与实现交接验收

- 我的页必须让用户快速找到：
  - 账号状态
  - 同步状态
  - 隐私与数据入口
  - 恢复购买入口
- 同步失败时，用户不能误以为本地数据已丢失。
- 会员入口必须可见，但不能压过账号与数据信任入口。
- 匿名态、登录态、会员态三种首屏层级必须明确区分。
- 若未来 Pencil 或实现稿把本模块推向“系统设置页”或“营销页”气质，必须回到冻结评审处理。
