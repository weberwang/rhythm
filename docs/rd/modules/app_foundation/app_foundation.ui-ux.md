# app_foundation UI/UX RD

> 配对实现 RD：`docs/rd/modules/app_foundation/app_foundation.impl.md`
> 全局基线：`docs/rd/2026-06-02-rhythm-commercial-global-rd.md`
> 工作流状态：`pen_ready`

## 1. 模块目标

建立全应用共享的视觉、导航、国际化、反馈和页面壳基础，让后续模块不重复造壳、不重复定义按钮、卡片、弹层和状态反馈，并让 `pen/v3.pen` 的页面层级可以稳定落进 Flutter。

## 2. 目标用户

所有 Rhythm 用户。该模块不直接承载单一业务任务，但决定用户对产品“清醒、温和、克制、有秩序”的整体感知，也是后续所有业务模块的显示层基线。

## 3. 页面范围与导航入口

- 启动壳
- 底部导航 Shell
- 一级页壳
- 二级页头
- 通用空态、错误、加载、轻提示
- 通用底部弹层壳和确认对话框壳

本模块不承载单独业务页，但会被以下页面家族共同消费：

- onboarding 首启链路
- 五个一级主页面
- 二级设置与详情页
- 全局弹层、确认框和轻提示

## 4. 核心用户路径

1. 用户打开 App。
2. 启动壳完成状态分发。
3. 用户进入 onboarding 或主 Shell。
4. 后续页面复用统一页面节奏、按钮、卡片、弹层和反馈。

这个模块对用户的真正价值不是“看到一个组件”，而是：

- 首屏不空白、不默认 Material
- 不同页面看起来属于同一个产品
- 错误、成功、权限、锁定状态有一致的语法
- 后续功能模块可以专注业务区块，而不是重复造基础壳

## 5. 状态矩阵

| 状态 | 设计要求 |
| --- | --- |
| loading | 品牌等待态，不出现纯空白页面 |
| empty | 提供下一步行动，不冷处理 |
| error | 页内解释和修复动作优先 |
| permission | 交给业务模块承载，基础层只提供容器 |
| partial data | 支持轻提示和说明卡 |
| disabled | 明确不可用原因 |
| success | 克制反馈，不做夸张庆祝 |
| locked | 只提供样式能力，触发策略由会员模块决定 |

## 6. 设计来源

唯一设计源为 `pen/v3.pen`。

进入 Pencil 核对时，本模块至少要读取这些设计对象：

- 启动分发页
- 一级主页面共用顶部结构
- 底部导航
- 二级页头
- 弹层与对话框总览
- 轻提示与反馈组件

如果 `v3.pen` 中缺少上述任一基础对象，必须先记录设计缺口，不能由 Flutter 侧自行补风格。

## 7. 现状诊断

当前代码已经具备一层可运行基础，但还没有形成足够稳定的基础层设计契约。

已具备：

- 全局主题和语义 token
- 页面骨架、Hero、主次按钮、表面卡片
- 启动页和路由壳
- 共享组件的基础测试

当前不足：

- `core` 和 `shared` 中同时长出 Hero / Card 家族，职责边界还不够清晰。
- 个别基础组件仍写死颜色、字体或背景色，说明 token 消费没有完全收口。
- `RhythmShell` 的底部导航仍更接近“默认导航换皮”，品牌层级还不够强。
- 页面壳需要统一“主焦点区、次级解释区、底部动作区”的结构约束，避免各业务页后续继续漂移。

## 8. 商业级设计方向

### 8.1 设计简报

- audience：所有 Rhythm 用户
- usage moment：首次打开、日常浏览、睡前进入、设置修改、错误恢复
- product promise：在所有状态下都让用户感到产品稳定、清楚、低压
- business goal：支撑激活、留存、信任和付费入口的一致基础体验
- page scope：应用壳、共享组件、全局反馈和页面骨架

### 8.2 平台基线

默认遵循 iOS HIG 交互基线：

- 安全区和触控尺寸合规
- 二级页保留推入返回语义
- 危险操作保留明确确认
- 底部导航保持稳定位置和清晰当前态

### 8.3 推荐艺术方向

- posture：`quiet assistant + precision tool`
- density：`balanced`
- visual temperature：`warm calm`，但保留一层清晨冷调秩序感
- de-native strategy：以 `hierarchy + material` 为主，不依赖插画堆砌
- brand memory：通过字体层级、表面关系、柔和深浅对比建立识别度
- polish lever：优先打磨页面节奏、表面体系和反馈语义，不优先堆动效

### 8.4 信息层级契约

- 每个页面只允许一个主焦点区。
- 主焦点区负责当前页面的核心任务或结果。
- 次级解释区负责说明、趋势或原因。
- 支撑区只承载次操作、轻提示或辅助入口。
- 底部固定动作区只承担明确命令，不与正文竞争注意力。

### 8.5 视觉系统契约

- Typography：标题、结果和正文必须通过主题 token 统一输出，不允许组件内继续散写字体家族。
- Spacing：一级页壳、二级页壳、弹层壳统一节奏，避免业务页自行决定段落密度。
- Surface：固定为页面背景、柔和表层、常规卡层、反色重点层四级。
- Color roles：状态色只表达语义，不做装饰。
- Radius：大圆角统一表达“温和可依赖”，不允许业务页随意扁平化。
- Motion：仅允许用于状态切换、进场和反馈，不用于装饰性摆动。

### 8.6 状态系统契约

- loading：必须是品牌等待态，不允许白屏或孤立 spinner
- empty：必须提供下一步
- error：必须提供修复动作
- permission：必须有补救或继续路径
- partial data：必须解释缺失什么
- success：必须低压克制
- locked：只提供展示容器，不在基础层决定拦截策略

## 9. 设计冻结卡

- 必须保持：统一页面壳、按钮高度、圆角、文字层级、反馈样式。
- 必须保持：一级页壳、二级页壳、弹层壳、确认框壳都由基础层统一输出。
- 必须保持：Hero、Card、Button、Feedback 只能保留一条主线，不允许 `core` / `shared` 双轨长期并存。
- 可工程化调整：阴影强度、背景渐变细节、局部动效、导航态细节。
- 不可偏离：不得让业务页面各自实现一套按钮、卡片、弹层和错误提示风格。
- 不可偏离：不得为了实现方便把基础层退回默认 Material 风格。

## 10. Pencil 交接门槛

- 进入 Pencil 前，先在 `v3.pen` 中确认基础页壳、导航、弹层和反馈节点是否完整。
- 若 `v3.pen` 已包含更高保真的导航、页壳或反馈样式，Flutter 基础层必须以后者为准收口。
- 若 `v3.pen` 中基础组件语义不稳定，先补设计冻结，不直接写代码。
- 若 `v3.pen` 为空文档，则本模块在 Pencil 阶段视为阻塞，必须先创建基础设计对象后再继续。

## 11. 验收门槛

- 共享壳不承载业务规则。
- 一级页和二级页有稳定结构。
- 弹层、对话框和 Snackbar 风格一致。
- 国际化入口可复用。
- 后续模块可以只专注业务区块设计。
- `pen/v3.pen` 成为唯一设计源后，不再继续引用 `app.pen` 或 `new-app.pen` 作为本模块标准。
