# goal_schedule UI/UX RD

> 配对实现 RD：`docs/rd/modules/goal_schedule/goal_schedule.impl.md`
> 全局基线：`docs/rd/2026-06-02-rhythm-commercial-global-rd.md`
> 工作流状态：`modules_split`

## 1. 模块目标

建立 Rhythm 的全局判断基准，让用户用低压力方式设置目标入睡、起床、熬夜阈值和一天起始时间。

## 2. 目标用户

首次激活用户和后续需要调整作息目标的回访用户。

## 3. 页面范围与导航入口

- onboarding 目标作息设置页
- 我的页中的目标作息编辑页
- 时区与特殊模式入口

## 4. 核心用户路径

1. 用户看到“目标可调整”的低压力说明。
2. 用户设置目标入睡和起床时间。
3. 用户确认熬夜阈值和一天起始时间。
4. 用户保存后，今日、日历、睡前、洞察都使用新基准。

## 5. 状态矩阵

| 状态 | 设计要求 |
| --- | --- |
| ideal | 表单短、默认值清晰 |
| loading | 保存中不重复提交 |
| error | 校验失败给出具体修正 |
| permission | 不涉及平台权限 |
| partial data | 目标不完整时提示补齐 |
| disabled | 高级策略未开放时解释边界 |
| success | 保存后给轻反馈 |
| locked | 双目标、轮班、时差策略可作为高级入口 |

## 6. 设计来源

核对 Pencil 中目标设置页、目标编辑页、时区与特殊模式页。高级策略若无设计稿，需先记录缺口。

## 7. 设计冻结卡

- 必须保持：目标时间是全局基准、目标可调整、表单低压力。
- 可工程化调整：时间选择器形态、阈值选择控件。
- 不可偏离：不得把设置页做成复杂系统配置页。

## 8. 验收门槛

- 用户能在 30 秒内完成基础目标。
- 文案不制造自责。
- 保存后下游页面基准一致。
- 高级策略不会阻断基础设置。
