# Bedtime Session UI/UX RD

## 模块目标与目标用户

- 模块目标：让用户在目标时间附近完成一个轻量的睡前收尾动作。
- 目标用户：到点被提醒的用户、从今日页主动进入的用户、会明显晚睡的用户。

## 页面范围与导航入口

- 页面范围：睡前页、倒计时区、今晚状态选择区、建议动作区。
- 导航入口：通知、小组件、今日页主动作入口。

## 平台基线

- 平台基线：`ios_hig`
- 说明：夜间页面的点击区、底部导航、文本可读性和单手操作路径遵循 iOS 基线，视觉强度继承全局冻结源。

## 商业目标

- 主要目标：提升睡前模式参与率，支撑北极星指标。
- 次要目标：让用户在情绪和疲劳状态下依然愿意完成一个小动作，而不是立刻退出。

## 艺术指导

- 产品姿态：`quiet assistant`
- 信息密度：`sparse`
- 视觉温度：`warm calm`
- 去原生重心：`typography and rhythm`
- 设计记忆点：大倒计时、低刺激背景、轻卡片动作建议构成“收尾而非打卡”的夜间气氛。

## 信息层级

- 主焦点区：距离目标入睡的时间差
- 次焦点区：今晚状态选择
- 支撑区：建议动作、目标时间、次级编辑入口
- 主动作：完成当前最轻的收尾动作
- 次动作：调整目标或稍后再处理

## 核心用户路径

1. 用户从通知或首页进入睡前页。
2. 用户看到距离目标入睡的时间差。
3. 用户选择今晚状态。
4. 系统给出一个轻量收尾动作。

## 状态矩阵

| 状态 | 表现要求 |
| --- | --- |
| 理想 | 3 次点击内完成核心路径，视觉低刺激 |
| 空态 | 无目标配置时，提示先建立作息目标 |
| 加载 | 读取当前计划与时间差时短暂骨架或平滑等待 |
| 错误 | 入口参数异常、会话保存失败要可恢复 |
| 权限 | 通知权限缺失不阻塞手动进入睡前页 |
| 部分数据 | 只有计划无昨晚反馈时，仍可完成今晚闭环 |
| 禁用 | 白天或不在提醒窗口时，允许进入但语义降级 |
| 成功 | 选择动作后给出克制确认，不要求打卡完成感 |
| 锁定/会员 | 本模块不承载核心付费锁定 |

## 设计冻结卡

- 当前状态：`approved_preview_baseline`
- 必须一致项：
  - 大倒计时始终是首屏唯一主焦点。
  - 状态选择卡与动作建议卡必须保持轻、克制、不带监督压迫感。
  - 夜间视觉不能出现高对比炫光、强告警红或重装饰背景。
- 允许工程化调整项：
  - 状态选择数量可在 3 个以内微调。
  - 倒计时布局可按真实动态内容做轻微适配。
- 平台不可偏离项：
  - 主操作必须在单手可达范围。
  - 夜间字体、对比度和点击区不能因审美削弱可读性。
- Prompt 约束：
  - 禁止把睡前页做成任务清单或效率清单。
  - 禁止多主焦点并列。
  - 禁止视觉上把“晚睡”做成惩罚警报。
- 冻结前必须确认：倒计时表达、状态选项数量、动作建议语气与夜间视觉强度。

## 视觉系统锚点

- 倒计时数字应使用高呼吸、轻重量、深松石系大字号。
- 建议动作卡可用主色强调，但同屏只保留 1 张高强调卡。
- 顶部导航和底部导航都必须退后于倒计时主焦点。

## UI/UX 与 Pencil 交接验收

- 夜间模式不得做强对比、强刺激视觉。
- 用户必须先读懂“距离目标还有多久”，再看到状态与动作。
- 建议动作只保留足够轻的收尾行为，不扩张成任务清单。
- 从通知 / 小组件进入时不能丢失上下文。
- 预览图已证明的“主焦点 + 轻动作卡 + 次级编辑”结构不得在重建中改写。
