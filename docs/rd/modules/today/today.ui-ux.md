## 1. 模块目标与目标用户

`today` 是 Rhythm 的每日回访入口。  
它服务的不是“想看一堆统计的人”，而是刚起床、刚回想昨晚、注意力有限、又希望今晚能稍微收一点的人。

在当前 `静夜秩序` 共享冻结下，`today` 的唯一主承诺是：

1. 先让用户平静地读懂昨晚结果
2. 再给出今晚目标
3. 再给一个明确但不命令式的下一步动作

## 2. 页面范围与导航入口

### 2.1 页面范围

- Today 顶层页
- 快捷补录入口
- 恢复建议摘要入口
- 睡前模式进入入口
- 趋势预告入口

### 2.2 导航入口

- 底部导航 `Today`
- onboarding 完成后的默认首落点
- 冷启动 / 热启动后的默认主页
- 通知、小组件、深链降级后的安全首页

### 2.3 页面归属

- `today` 负责首页内容层级、结果解释和入口组织
- `app-shell` 负责顶层壳层与来源分发
- `sleep-data-core` 负责提供记录、目标、恢复与聚合基础结果

## 3. 核心用户路径

### 3.1 正常回访路径

1. 用户进入 Today。
2. 首屏先读到昨晚结果主卡。
3. 结果主卡下方看到今晚目标与收尾边界。
4. 再看到下一步动作，例如开始收尾或进入 Bedtime。
5. 若还有余力，可继续查看轻趋势。

### 3.2 结果缺失路径

1. 用户进入 Today。
2. 结果区明确说明当前判断不完整。
3. 用户可快速进入补录或修正路径。
4. 即使无数据，今晚目标与下一步动作仍然可用。

### 3.3 明显晚睡路径

1. 用户先看到真实但不羞辱的偏移结果。
2. 系统在目标卡或支持说明中提示今晚收缩范围。
3. 用户通过下一步动作进入温和恢复路径。

### 3.4 睡前切换路径

1. 用户从 Today 首页进入 Bedtime。
2. Today 保留“为什么要收尾”的上下文。
3. Bedtime 承接“现在怎么收尾”的执行动作。

## 4. 页面级结构与区块层级

### 4.1 首屏固定阅读顺序

1. 页面标题与一句轻说明
2. 昨晚结果主卡
3. 今晚目标卡
4. 下一步动作卡
5. 7 天趋势摘要块
6. 更深层补录、恢复详情或付费入口

### 4.2 首屏重点区块

#### 结果主卡

- 承载昨晚偏移的核心陈述
- 顶部需要同时给出结果眉题与结果日期
- 下半区需要补充睡眠窗口与 rhythm 判断两列支持信息
- 使用更强的 serif 大字排版
- 必须是首屏第一视觉重心

#### 今晚目标卡

- 承载目标入睡时间、收尾时间和轻恢复说明
- 右上角允许存在低刺激状态 chip，用于表达“small reset”这类今晚姿态
- 视觉强度低于结果卡，高于动作卡

#### 下一步动作卡

- 承载主 CTA 与最小执行建议
- 默认采用“左文案 + 右按钮”的低压横向构图
- 必须清晰可达，但不允许压过结果卡

#### 趋势摘要块

- 只作为轻量模式感知
- 默认使用低强调的 weekday 状态点阵与紧凑 legend，而不是仪表盘式图表
- 不得争抢首屏层级

## 5. 状态矩阵

| 状态 | 触发条件 | 承载位置 | 交互目标 | UI 处理 |
| --- | --- | --- | --- | --- |
| ideal | 数据完整且有今晚目标 | 首屏主内容区 | 先理解，再行动 | 结果卡优先，目标与动作次之 |
| loading | 记录或目标加载中 | 各主卡骨架位 | 保持结构记忆 | 骨架不闪烁，版式稳定 |
| empty | 无记录或首日使用 | 结果区 / 目标区 | 仍可开始今晚 | 说明无历史，但今晚仍可建立第一步 |
| error | 同步失败或聚合失败 | 页内状态位 | 不阻断继续使用 | 显示轻说明并保留本地路径 |
| permission | 健康权限未授权 | 顶部说明区或结果区 | 解释价值并给替代方案 | 不强压授权 |
| partial_data | 数据延迟或部分缺失 | 结果卡 / 趋势区 | 提醒当前判断不完整 | 明示缺口，不装作精确 |
| disabled | 某入口暂不可用 | 快捷入口 | 说明原因 | 不干扰主 CTA |
| success | 昨晚达标或已完成补录 | 结果区 | 克制正反馈 | 仍保持冷静语气 |
| locked | 恢复详情锁定 | 次级恢复入口 | 展示价值后升级 | 不可压过首屏主任务 |

## 8. 交互规则与恢复路径

### 8.1 结果主卡

- 用户无需展开即可读懂昨晚核心偏移
- 结果陈述必须优先于任何 CTA
- 支持信息只能作为结果解释的第二层，不得反客为主
- 结果卡不承载复杂筛选或二级导航

### 8.2 今晚目标卡

- 用户应一眼看到目标时间和收尾边界
- 若昨晚明显晚睡，可在此处承载轻恢复说明
- 状态 chip 只能表达今晚姿态，不能替代目标时间本体
- 不允许把目标卡做成设置页风格

### 8.3 下一步动作卡

- CTA 文案必须是安静邀请型
- CTA 可进入 Bedtime 或触发收尾动作
- 按钮可右置，但按钮尺寸和色块面积不得压过结果卡
- 不能让用户在此卡中填重表单

### 8.4 缺失 / 异常恢复路径

- 数据缺失时，优先提供补录 / 修正
- 同步失败时，优先提供继续本地查看
- 权限缺失时，说明价值并给手动替代路径

## 9. 边界状态与不可回退约束

### 9.1 必须保留的约束

- 首屏第一重心必须是昨晚结果主卡
- 今晚目标卡必须位于结果卡之后、动作卡之前
- 趋势摘要不得挤进首屏主层级
- 付费入口、历史摘要、恢复详情入口不得压过结果卡

### 9.2 允许工程调整的点

- 趋势摘要块的具体图形形式
- 快捷入口的布局密度
- 极浅阴影和表面层次的 Flutter 化细节

## 12. 验收门

### 12.1 UI/UX 验收

- 首屏 3 秒内可读懂昨晚结果和今晚目标
- 主 CTA 在结果与目标之后自然可达
- 首页不退回仪表盘或行动先行页

### 12.2 模块设计冻结验收

- 结果主卡、目标卡、动作卡的主次顺序稳定
- 空态、权限态、部分数据态、锁定态都有明确承载
- 趋势区和付费入口不抢主层级

### 12.3 代码交接验收

- Today 对 `sleep-data-core` 的聚合依赖边界清晰
- Today 与 Bedtime 的职责切分清晰
- Today 的结果解释口径由统一内部模型提供

## 13. 开放问题

- 恢复详情锁定与免费摘要的边界文案仍需商业侧最终确认。
- 趋势摘要块的交互深度仍需后续模块冻结时再精细化。
