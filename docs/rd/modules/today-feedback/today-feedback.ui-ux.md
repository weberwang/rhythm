# Today Feedback UI/UX RD

## 模块冻结定位

- 模块定位：`Today Feedback` 是 Rhythm 的日回访首页主入口，用最短阅读路径告诉用户“昨晚结果如何、今晚目标是什么、现在下一步做什么”。
- 冻结状态：`frozen_for_architecture`
- 设计源继承：
  - 强制继承 [docs/rd/global-design-guidelines.md](D:/Projects/Flutter/rhythm/docs/rd/global-design-guidelines.md) 的 `design_position`、`global_experience_principles`、`information_hierarchy_principles`、`layout_and_page_structure_principles`、`state_and_feedback_principles`、`design_prohibitions`。
  - 强制继承 [docs/rd/light-theme-freeze.yaml](D:/Projects/Flutter/rhythm/docs/rd/light-theme-freeze.yaml) 与 [docs/rd/dark-theme-freeze.yaml](D:/Projects/Flutter/rhythm/docs/rd/dark-theme-freeze.yaml) 的全部语义色角色，不允许模块局部另起主题。
  - 本模块只允许在“同一语义角色的版式落位”上工程化调整，不允许偏离 `warm calm`、克制、细边框卡片、松石主色、非 dashboard 的全局冻结方向。

## 模块目标与目标用户

- 模块目标：让用户回到应用 3 秒内完成结果识别与动作判断，建立“产品正在帮我回到节奏”的第一感知。
- 目标用户：
  - 日常回访用户
  - 刚从通知、小组件、启动回流的用户
  - 昨晚明显晚睡、需要恢复建议承接的用户
  - 刚完成同步或手动补录、需要确认结果的用户

## 页面范围与导航入口

- 页面范围：今日页主屏、首页摘要区块、与今日页直接绑定的快捷动作区。
- 导航入口：
  - 主导航首页
  - 启动完成后的默认首页
  - 通知回流
  - 小组件回流

## 平台基线

- 平台基线：`ios_hig`
- 平台说明：
  - 安全区、底部导航、滚动回弹、按钮触达区、骨架加载、弹层确认遵循 iOS 预期。
  - 首屏主动作必须单手可达，避免要求用户跨屏寻找主入口。
  - 不使用 Android 式高密度信息墙，也不退回系统设置式列表首页。

## 商业目标

- 主要商业目标：提高日回访留存与首页可感知价值，避免用户把产品理解成“记录完就结束”的低粘性工具。
- 次级商业目标：在用户已经读懂昨晚结果之后，顺势承接恢复建议、长期洞察与会员价值，而不是抢占首页主任务。
- 商业成功信号：
  - 用户先完成首页阅读与主动作，再进入洞察或会员触点。
  - 明显晚睡日的恢复建议被看见，但不制造羞辱感。

## 艺术指导

- 产品姿态：`quiet assistant`
- 信息密度：`balanced`
- 视觉温度：`warm calm`
- 视觉语气：可信、轻度照护、非庆典、非惩罚
- 页面记忆点：`昨晚结果主卡 + 今晚行动次卡 + 轻量恢复摘要` 的纵向连续节奏，而不是并排 KPI 卡片墙。
- 风格限制：
  - 不得出现 dashboard 式高密度统计矩阵。
  - 不得出现医疗警报感红色头图。
  - 不得用大面积渐变或重阴影制造“营销主屏”观感。

## 信息层级

- 一级信息：
  - 昨晚结果
  - 相对目标偏移
- 二级信息：
  - 今晚目标
  - 当日唯一主动作
- 三级信息：
  - 恢复建议摘要
  - 7 天趋势摘要
  - 快捷补录 / 详情入口
- 四级信息：
  - 会员深层洞察入口
  - 设置或管理入口
- 固定阅读顺序：
  1. 页面身份
  2. 昨晚结果
  3. 今晚下一步
  4. 恢复解释
  5. 次级管理入口

## 核心用户路径

1. 用户打开今日页。
2. 用户在首屏读懂昨晚结果与相对目标偏移。
3. 用户读到今晚目标与当前唯一主动作。
4. 若存在明显晚睡或恢复需求，用户继续浏览恢复建议摘要。
5. 用户再决定进入补录、趋势详情或高级洞察。

## 状态矩阵

| 状态 | 表现要求 |
| --- | --- |
| 理想 | 首屏只保留一个主焦点，其他信息必须明显降级 |
| 空态 | 先解释如何开始记录，再给一个可执行起步动作，不展示空图表 |
| 加载 | 允许主卡和次卡分区 skeleton，禁止整页遮罩式等待 |
| 错误 | 聚合失败或同步失败时局部可恢复，不能让首页整体失语 |
| 权限 | 无健康权限时先解释价值，再给手动记录路径 |
| 部分数据 | 有计划无结果、有结果无标签、有结果无趋势都要分别说明 |
| 禁用 | 高级洞察锁定只锁次层内容，首页主结果始终可见 |
| 成功 | 达标反馈克制，不做庆祝式游戏化奖励 |
| 锁定/会员 | 会员触点必须出现在已读懂主结果之后，不能抢占主卡位置 |

## 模块级组件冻结骨架

- `last_night_result_card`
  - 用途：承载昨晚结果、相对目标偏移和主解释文案。
  - 状态：`default`、`late_offset`、`on_target`、`partial_data`。
  - 冻结约束：首屏只能有这一张主结果卡承担 dominant zone，不得与趋势卡并列争主。
- `tonight_plan_card`
  - 用途：承载今晚目标和当前唯一主动作。
  - 状态：`default`、`action_ready`、`action_unavailable`、`needs_setup`。
  - 冻结约束：必须紧跟主结果卡出现，不得被趋势、营销或设置入口隔开。
- `recovery_summary_card`
  - 用途：承载恢复建议摘要和当日重点解释。
  - 状态：`default`、`high_recovery_need`、`light_hint`、`locked_detail`。
  - 冻结约束：只在高恢复需要时前置，正常日不能制造额外压力。
- `quick_action_strip`
  - 用途：承载补录、查看详情、进入睡前模式等快捷动作。
  - 状态：`default`、`partial_available`、`disabled`。
  - 冻结约束：总数上限 `3`，不得扩张成多入口宫格。

## 设计源与模块继承合同

- Pencil 来源：当前模块 UI/UX 冻结先以前述全局冻结文件为唯一设计源；如后续接入 Pencil，必须以 Pencil 与全局冻结一致的页面结构为准，不得反向稀释冻结约束。
- 全局继承重点：
  - 继承“永远先告诉用户现在发生了什么，再告诉用户下一步做什么”的全局体验原则。
  - 继承“同屏只允许 1 个高强调面”的版式原则。
  - 继承“锁定内容必须明显晚于已可用内容出现”的商业表达原则。
- 主题继承重点：
  - Light 主题首页主卡以浅表面和深松石文字层级建立可信感。
  - Dark 主题保留明确卡片边界，不允许把卡层融成一整片深色背景。

## 设计冻结卡

- 当前状态：`frozen_for_architecture`
- 必须一致项：
  - 首屏只能有一个主结果焦点，不得把趋势、会员、营销入口提升为并列主角。
  - 昨晚结果必须和“相对目标偏移”绑定出现，不能只给一个孤立分数或标签。
  - 今晚目标与当前主动作必须在主结果之后立即可见，避免用户需要滚动寻找下一步。
  - 恢复建议仅在明显偏移、连续晚睡或高需要时前置，正常日不得制造额外心理负担。
  - 会员入口只能作为次级卡片或卡内次动作，不得挤占首页主闭环。
- 允许工程化调整项：
  - 主卡高度可因数字长度、说明文案或语言变化弹性伸缩。
  - 局部 skeleton、趋势微图、图标姿态可按 Flutter 组件实现做轻微变化。
  - 快捷动作可在 `2-3` 个上限内做排序调整，但不能扩张成入口宫格。
- 平台不可偏离项：
  - 底部导航语义保持稳定，不把首页主操作塞进导航条。
  - 主按钮、主卡点击区必须满足疲劳状态下的舒适触达。
  - 破坏性操作不得出现在今日页主层级。
- Prompt 约束：
  - 禁止首页出现多主卡竞争。
  - 禁止做成医疗仪表盘、效率 KPI 看板或晨报信息墙。
  - 禁止用高饱和红、强警报词或羞辱式文案表达晚睡。
  - 禁止把会员营销做成首屏最强对比块。

## 视觉系统锚点

- 主结果卡：
  - 优先使用 `surface / surface_elevated` 与细边框建立层次，不依赖厚重阴影。
  - 关键数字与结果标题允许使用更高识别度排版，但仍保持轻重量、宽呼吸。
- 今晚动作卡：
  - 作为次焦点层，视觉强调弱于主结果卡，但必须比趋势和管理入口更醒目。
  - 可以使用浅松石强调底或边界强调，不能变成第二个主英雄卡。
- 恢复摘要与趋势卡：
  - 保持细边框、低对比、宽留白。
  - 趋势摘要只做“支撑解释”，不升级成多图表信息墙。
- 模块级视觉约束：
  - 同屏高强调面数量上限为 `1`。
  - 快捷入口不得采用四宫格或八宫格。
  - Dark 模式下边框必须保留，不能让卡片与背景失去分层。

## 商业化触点

- 轻量商业触点：
  - 恢复建议详情
  - 稳定度深层解释
  - 长期趋势入口
- 商业化呈现规则：
  - 先给免费结果与即时帮助，再给更深洞察价值。
  - 价值叙事必须围绕“持续改善、长期回稳、理解自己”，而不是“解锁更多图表”。
  - 商业触点只承接高意图行为，不主动打断首页主任务。

## UI/UX 与实现交接验收

- 首页首屏必须同时回答：
  - 昨晚怎么样
  - 今晚目标是什么
  - 现在下一步是什么
- 当晚睡偏移明显时，恢复建议必须在首屏或首屏后一屏内可见。
- 快捷操作必须服务闭环，不允许演变成杂项入口集合。
- 真实数据接入后，数字长短、标签有无、说明增减都不能破坏排版层级。
- 若后续 Pencil 设计稿与本文件不一致，必须回到模块冻结评审，不允许实现侧自行裁剪。
