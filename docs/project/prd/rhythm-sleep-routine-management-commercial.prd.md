# Rhythm 作息行为管理 PRD

## 1. 背景与问题陈述

Rhythm 面向长期晚睡、反复拖延入睡、但主观上愿意调整作息的人群。当前主流睡眠产品更擅长记录结果、展示图表和输出抽象分数，却不擅长解决用户今晚为何停不下来、次日如何理解偏离、以及熬夜后如何恢复节奏这三个高频问题。

现在做这件事的原因有三点：

- 行为改善类产品正从“记录更多数据”转向“帮助用户完成下一步动作”。
- iOS 侧健康数据与本地提醒能力已经足以支撑首发验证闭环。
- 用户对“非医疗化、低羞耻感、可持续恢复”的作息管理产品存在明确空白。

如果问题持续不被解决，用户会继续在“白天后悔、晚上拖延、第二天自责”的循环里打转，最终把产品视为又一个只能看图、不能帮助改变行为的工具。

## 2. 目标与成功标准

### 2.1 业务目标

- 验证一条可持续回访的作息行为闭环，而不是一次性报告型产品。
- 证明免费层可以建立信任，付费层可以围绕“持续改善”形成购买理由。
- 为后续技术基线、设计方向确认、模块拆分和移动端实现提供稳定输入。

### 2.2 用户结果目标

- 用户能在首次使用时快速进入可用状态。
- 用户能在目标入睡前获得轻量、可执行的收尾引导。
- 用户能在次日理解晚睡偏离，而不是只收到抽象评价。
- 用户能在晚睡后看到恢复建议，并愿意继续使用。

### 2.3 成功标准

核心北极星指标：

- 最近 7 天内有 3 天以上有效记录，且至少 1 次进入睡前模式的活跃用户数。

首发验收指标：

| 维度 | 指标 | 目标 |
| --- | --- | --- |
| 激活 | 进入可用状态完成率 | >= 70% |
| 授权 | 健康数据授权率 | >= 55% |
| 设置 | 目标作息设置完成率 | >= 65% |
| 首晚 | 首晚记录生成率 | >= 40% |
| 行为 | 睡前模式周使用率 | >= 25% |
| 反馈 | 原因标签补录率 | >= 30% |
| 留存 | D7 留存 | >= 25% |
| 留存 | D30 留存 | >= 12% |
| 商业化 | 订阅转化率 | 3%-5% |

### 2.4 预警标准

- 授权率偏低，说明权限价值表达或信任建设不足。
- 睡前模式进入率偏低，说明闭环入口与晚间价值感不足。
- D7 可接受但 D30 偏低，说明短期新鲜感存在、长期行为价值不足。
- 付费墙曝光高但转化低，说明高级能力没有被表达为“改善结果”。

## 3. 目标用户与角色

### 3.1 主要角色

- 长期晚睡但有调整意愿的移动端用户。
- 年龄段以 20-35 岁为首发优先。
- 典型场景包括远程办公者、城市白领、学生与年轻职场新人。

### 3.2 次要角色

- 跨时区或经常出差的用户。
- 后续可能覆盖的轮班用户。

### 3.3 角色差异

- 匿名本地用户：优先完成首发闭环，不依赖登录即可开始记录、查看反馈和进入睡前模式。
- 已登录用户：额外获得跨设备同步、订阅状态恢复和长期数据备份能力。
- 订阅用户：获得恢复计划详情、长期历史、稳定度解释、双目标、轮班/时差策略和高级报告。

## 4. 核心场景与用户旅程

### 4.1 首次激活路径

1. 用户理解产品不是医疗诊断工具，而是作息行为管理工具。
2. 用户选择匿名本地开始或登录。
3. 用户授权睡眠数据，或转入手动补录路径。
4. 用户设置目标入睡时间、起床时间、熬夜阈值和一天起始时间。
5. 用户配置提醒策略。
6. 用户进入今日页并看到首个可用状态。

### 4.2 晚间执行路径

1. 到达提醒时间。
2. 用户从通知、小组件或今日页进入睡前模式。
3. 页面展示距离目标入睡还有多久，以及当前建议动作。
4. 用户选择今晚状态并执行轻量收尾动作。
5. 系统记录行为线索，供次日解释使用。

### 4.3 次日反馈路径

1. 用户打开 App。
2. 今日页展示昨晚结果、偏移程度和连续表现。
3. 用户补充晚睡原因标签。
4. 系统在明显晚睡时优先展示恢复建议。
5. 用户看到今天目标与一周趋势。

### 4.4 周复盘路径

1. 系统按固定频率生成周报。
2. 用户查看达标率、稳定度、最晚入睡日、主要原因和建议。
3. 用户决定是否调整目标、查看高级解释或进入付费能力。

### 4.5 关键失败与回退路径

- 健康数据拒绝授权时，必须无损切换到手动补录。
- 登录失败时，必须允许回到匿名本地使用。
- 自动数据缺失或晚到时，必须提示当前判断不完整，并提供补录或重试入口。
- 同步、通知、订阅等增强能力失败时，不得阻断本地主闭环。

## 5. 范围内功能

### 5.1 P0 首发闭环功能

- 睡眠数据接入。
- 手动补录与手动修正。
- 目标作息设置。
- 睡前柔性提醒、到点提醒、周报提醒。
- 今日页结果反馈。
- 月历热力图与单日详情。
- 睡前模式。
- 晚睡原因标签。
- 基础恢复建议。
- 基础周报。
- 基础小组件入口。

### 5.2 P1 商业化承接功能

- 会员体系基础能力。
- 恢复计划详情。
- 稳定度解释。
- 历史数据边界与付费承接。
- 账号同步与订阅状态恢复。

### 5.3 P2 长期差异化功能

- 工作日 / 休息日双目标。
- 轮班 / 时差策略。
- 月报与高级报告。
- 高级小组件。

### 5.4 关键功能要求

- 免费层必须先证明价值，再承接升级。
- 所有核心页面都要回答“我现在应该做什么”。
- 所有判断以用户目标时间为参照，而不是固定医学阈值。
- 晚睡后的第一反馈必须优先指向恢复，而不是惩罚。

## 6. 明确不做

- 医疗诊断、治疗、治愈相关能力与表述。
- 冥想内容、白噪音库、睡眠内容陪伴产品。
- 社区陪伴、情侣监督、排行榜、强打卡惩罚。
- 深度医学评分与复杂生理指标解释。
- 硬件联动与实时监测作为首发范围。
- AI 聊天教练、年度人格报告、主题商店等非核心闭环能力。
- 桌面端或 Web 作为首发验证面。

## 7. 关键状态与异常场景

| 状态 | 影响范围 | 处理要求 |
| --- | --- | --- |
| 首次加载 | 启动页、引导页、今日页 | 需要品牌化等待态，避免空白 |
| 健康权限未授权 | 引导页、今日页、我的页 | 明确授权价值，并提供手动路径 |
| 权限已授权但无数据 | 今日页、日历页 | 解释数据延迟，允许补录 |
| 数据同步失败 | 今日页、我的页 | 页内提示、重试入口、保持本地可用 |
| 登录失败 | 登录页 | 明确失败原因，允许匿名继续 |
| 手动修正 | 今日页、单日详情 | 标注来源，不静默覆盖原始记录 |
| 昨晚达标 | 今日页、日历页 | 正向但克制的反馈 |
| 轻微偏离 | 今日页、日历页 | 给出温和下一步建议 |
| 明显晚睡 | 今日页、洞察页 | 恢复建议前置 |
| 标签为空 | 次日反馈、单日详情 | 提供轻量标签入口 |
| 历史数据锁定 | 日历页、洞察页 | 先展示免费边界，再解释升级收益 |
| 恢复计划锁定 | 今日页、洞察页 | 只在高意图场景触发升级 |
| 时区变化 | 今日页、日历页、我的页 | 暂停普通判断，要求用户确认 |
| 网络不可用 | 登录、同步、会员 | 降级可用，不阻断本地主闭环 |
| 通知权限关闭 | 提醒相关入口 | 说明影响，保留手动进入睡前模式能力 |

额外状态要求：

- 必须覆盖空、加载、错误、权限拒绝、部分数据、长内容、短内容场景。
- 关键状态不能只靠颜色表达，必须配合文案或图标。

## 8. 数据、权限与外部依赖

### 8.1 关键数据对象

- `User`：地区、语言、时区、会员状态、登录状态。
- `GoalSchedule`：目标入睡、目标起床、熬夜阈值、一天起始时间、工作日规则。
- `SleepRecord`：日期、入睡、起床、时长、数据来源、可信状态、修正状态。
- `BedtimeSession`：进入时间、触发方式、今晚状态、建议动作、完成状态。
- `SleepDelayTag`：日期、原因标签、自定义标记、推荐标记。
- `RecoveryPlan`：触发原因、计划周期、建议动作、完成状态。
- `Report`：达标率、稳定度、主要原因、建议摘要。

### 8.2 关键计算

- 达标：实际入睡时间小于等于目标入睡时间加熬夜阈值。
- 晚睡分钟数：实际入睡时间减目标入睡时间。
- 稳定度：最近 7 天入睡时间偏差的简化模型。
- 周达标率：最近 7 天达标天数除以有效记录天数。
- 恢复成功：触发恢复计划后的 3 天内至少 2 天回到阈值内。

### 8.3 权限与依赖

- 系统健康数据能力：作为自动睡眠记录的首发数据来源。
- 本地通知：支撑柔性提醒、到点提醒和周报提醒。
- 本地存储：支撑目标设置、标签、补录与离线可用。
- 账号体系与云同步：支撑跨设备恢复、订阅同步和长期备份。

### 8.4 依赖边界

- 自动数据不可用时，手动补录必须是一等路径。
- 提醒权限关闭时，不得阻断今日页、日历页和睡前模式主流程。
- 登录与同步默认是增强能力，不是首用前提。
- 外部供应商、具体同步后端与订阅 SDK 的最终选型留给技术基线阶段确认。

## 9. 平台与体验边界

### 9.1 平台边界

- 产品范围：移动端优先。
- 首发验证面：iOS 真机优先。
- Android：作为后续正式版本补齐平台，而不是当前首发验证面的前置条件。

### 9.2 体验边界

- 产品是“作息行为管理”而不是“睡眠医学诊断”。
- 信息层级要以今晚任务和次日解释为核心，不做图表堆砌。
- 体验姿态是温和、克制、低压迫，而不是监督、惩罚和打卡。
- 不在 PRD 阶段冻结具体 UI 结构、页面分辨率和详细视觉方案。

### 9.3 商业边界

- 免费层负责建立信任和基础闭环。
- 付费层围绕恢复、稳定、长期改善展开，不围绕“多几张图”展开。
- 付费触点只出现在高意图节点，不提前打断激活。

## 10. 约束条件

### 10.1 合规与隐私

- 禁止使用治疗、诊断、治愈、医学改善、精准评估失眠等表述。
- 必须提供隐私政策入口、订阅条款入口、健康数据读取范围说明。
- 必须保留数据导出或删除路径说明。

### 10.2 国际化

- 所有用户可见文案必须进入国际化资源体系。
- 中文和英文作为首批支持语言基线。
- 体验逻辑不能依赖中文特有语义才能成立。

### 10.3 可访问性

- 关键状态不能只靠颜色传达。
- 睡前模式必须保证夜间低刺激下仍然可读、可点、可区分。
- 付费墙、通知文案和关键按钮必须避免认知歧义。

### 10.4 性能与交付

- 首次安装到进入可用首页时间不超过 2 分钟。
- 睡前模式关键路径不超过 3 次点击。
- 首发范围按 P0 / P1 / P2 严格分层，避免首发闭环失控。

## 12. 假设、风险与后续事项

### 12.1 核心假设

| 假设 | 理由 | 如果错误的风险 |
| --- | --- | --- |
| 用户愿意为了更稳定的作息而非更多图表付费 | 原始文档商业逻辑明确以“持续改善”为核心 | 付费层可能需要重新定位 |
| 匿名本地使用会提升激活完成率 | 降低登录摩擦最符合首发闭环 | 后续同步转化可能低于预期 |
| 手动补录保留为一等路径能提升闭环完整性 | 权限拒绝不应导致产品失效 | 数据质量会更不稳定，需要更强来源标识 |
| 中英双语资源预埋能降低后续国际化返工 | 项目已要求全部用户文案走国际化链路 | 首发文案成本略有增加 |

### 12.2 主要风险

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| 健康数据授权率低 | 激活受损 | 强化授权价值说明，保持手动路径同等可达 |
| 睡前模式进入率低 | 北极星指标无法成立 | 优化提醒时机、入口密度和睡前页首屏价值 |
| 自动数据延迟或缺失 | 用户信任下降 | 明示数据来源与延迟状态，提供补录与修正 |
| 付费叙事过弱 | 转化率低 | 用恢复、稳定、长期改善重构付费表达 |
| 视觉方向过度疗愈化或过度工具化 | 品牌与商业调性失衡 | 在后续设计方向确认阶段严格冻结边界 |
| 首发范围膨胀 | 交付节奏失控 | 严格按 P0 / P1 / P2 分层推进 |

### 12.3 后续事项

- 下一阶段应基于本 PRD 生成全局技术基线。
- `--preview` 请求已记录，但在当前 PRD 阶段不生成任何视觉预览。
- 页面级视觉方向、设计设备预设、结构化设计源适配器选择，均留待设计分支阶段确认。
